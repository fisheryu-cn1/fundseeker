# 多期持仓数据下的聚类分析展示需求建议

## 1. 背景与目标

### 1.1 当前现状

当前 FundSeeker 的聚类分析以单一持仓报告期（`report_date`）为截面进行 K-Means 聚类，结果持久化到 `similarity_cluster_run`、`similarity_clusters`、`similarity_cluster_members` 等表中。前端页面支持：

- `/similarity`：按 `report_date` 和 `algorithm` 筛选单次聚类运行；
- `/similarity/compare`：跨运行的 silhouette/k 等元指标对比；
- `/similarity/<run_id>`：展示单期聚类结果（簇列表、行业矩阵、期间涨跌）；
- `/similarity/<run_id>/cluster/<id>`：展示单簇详情（成员、top 持仓/行业、净值对比）；
- `/similarity/products/<id>`：展示某产品在不同聚类运行中的归属记录。

### 1.2 新需求

随着持仓数据跨多期积累（例如 2026-03-31 和 2026-06-30 两个季报期），用户希望在前端指定一个观察时间区段（如 2026-04-01 至 2026-06-20）查看聚类分析结果，并期望系统能够：

1. 当区段内持仓数据没有更新时，自动回退到最近可用报告期的聚类结果；
2. 当区段跨越多个持仓报告期时，不仅不强制“只能选单一期”，还能有效呈现多期聚类差异；
3. 结合不同时间点的持仓变化和市值变化，从聚类角度输出对投资决策有参考意义的分析。

### 1.3 目标

本建议文档提出一套可落地的多期聚类展示方案，明确时间区段解析规则、前端交互模式、后端计算逻辑和投资分析维度，供后续排期开发参考。

## 2. 核心设计原则

| 原则 | 说明 |
|---|---|
| **报告期驱动，区段映射** | 聚类结果只能锚定在真实的持仓报告期上；用户选择的时间区段必须先映射到一个或多个报告期，再展示对应聚类。 |
| **近者优先** | 当区段内没有新的持仓报告期时，使用区段起点之前最新的报告期，避免无结果。 |
| **不强制单期，支持对比** | 跨报告期时优先提供“双期/多期对比”视图，而非简单提示用户拆分。 |
| **差异即信号** | 多期聚类的核心价值在于“变化”：簇的存续、分裂、合并、成员流动、主题漂移。 |
| **可解释 > 可炫技** | 所有聚类差异必须落到具体产品、行业、重仓股和收益数字上，避免只展示抽象的矩阵。 |

## 3. 时间区段与报告期对齐规则

### 3.1 数据基础

- `HoldingReport.report_date`：真实的持仓快照日期（如 2026-03-31、2026-06-30）。
- `SimilarityClusterRun.report_date`：聚类运行所基于的报告期，与 `HoldingReport.report_date` 对齐。

### 3.2 对齐算法

给定用户选择的时间区段 `[start_date, end_date]`，系统按以下规则确定“有效报告期”：

```
1. 列出所有 <= end_date 的持仓报告期，按日期降序排列。
2. 如果列表为空，返回“无可用持仓数据”。
3. 找到最大的 report_date 满足 report_date <= start_date，记为 R0（区段起点前的最新报告期）。
4. 找到区间内（start_date <= report_date <= end_date）的所有报告期，记为 R1, R2, ... Rn。
5. 有效报告期集合 = {R0} ∪ {R1..Rn}，按时间升序排列。
```

**示例**：

| 用户选择区段 | 可用报告期 | 有效报告期 | 模式 |
|---|---|---|---|
| 2026-04-01 ~ 2026-06-20 | 03-31, 06-30 | 03-31 | 单期（区间内无更新） |
| 2026-04-01 ~ 2026-07-10 | 03-31, 06-30 | 03-31, 06-30 | 双期对比 |
| 2026-01-01 ~ 2026-07-10 | 03-31, 06-30 | 03-31, 06-30 | 双期对比（起点前无更早报告期） |
| 2026-07-01 ~ 2026-07-10 | 03-31, 06-30 | 06-30 | 单期（区间内无更新，回退到最近） |

### 3.3 前端提示

- 在界面上明确标注“当前展示基于报告期：2026-03-31 持仓数据”。
- 当区段映射到多个报告期时，提示“该区段跨越 N 个持仓报告期，已进入对比模式”。

## 4. 多期聚类展示模式

### 4.1 模式一：单期快照（区间内无更新）

当有效报告期只有一个时，直接展示该报告期的聚类结果，与当前 `/similarity/<run_id>` 页面一致。

### 4.2 模式二：双期对比（推荐默认）

当有效报告期为两个时，系统默认进入双期对比视图。该模式是投资分析中最常用的场景（相邻两季度）。

#### 4.2.1 页面布局

建议新增独立页面 `/similarity/evolution?start=...&end=...`，核心模块如下：

| 模块 | 内容 |
|---|---|
| **时间轴头图** | 展示两个报告期及区段内的市场指数走势（沪深300、中证500等），提供时间上下文。 |
| **运行级 KPI 对比** | 两个报告期的 k、产品数、silhouette、inertia、特征维度对比。 |
| **簇生命周期矩阵** | 以 Sankey/流向图或表格形式展示旧簇 → 新簇的成员流动。 |
| **主题漂移列表** | 列出主题标签（由 top_industries 派生）的“存续/新增/消失”状态。 |
| **核心产品流动表** | 列出从一个簇迁移到另一个簇的代表性产品。 |
| **收益分化榜** | 对同一旧簇在新报告期中分化的产品，按期间收益排序。 |

#### 4.2.2 簇生命周期判定

对两期聚类结果，按成员重叠率判断簇之间的关系：

```python
overlap_ratio(A, B) = len(members(A) ∩ members(B)) / min(len(A), len(B))
```

| 关系 | 判定条件 | 前端展示 |
|---|---|---|
| 存续 | overlap_ratio >= 0.5 | 同一行/同一颜色，标注成员变化数 |
| 分裂 | 旧簇 A 的成员分散到多个新簇，且每个新簇 overlap < 0.5 | 旧簇 → 多个新簇的流向 |
| 合并 | 多个旧簇的成员主要流入同一个新簇 | 多个旧簇 → 一个新簇的流向 |
| 消失 | 旧簇没有任何新簇 overlap >= 0.3 | 标记为“衰退/消失” |
| 新增 | 新簇没有任何旧簇 overlap >= 0.3 | 标记为“新兴” |

#### 4.2.3 主题漂移判定

基于 `cluster_label` 或 `top_industries`：

- 若两个簇存在映射关系（存续/分裂/合并），比较它们的 top_industries 权重变化；
- 新增/消失的行业即为漂移信号；
- 可生成“行业热度变化”条形图（本期权重 - 上期权重）。

### 4.3 模式三：多期时间轴（3 期及以上）

当有效报告期 >= 3 时，提供“聚类演化时间轴”视图。

#### 4.3.1 页面内容

- **簇数量时序图**：每期 k 值、簇平均大小、最大簇占比。
- **主题热度时序图**：按行业/主题聚合，展示各主题在不同报告期的总权重或簇数量。
- **核心主题存续图**：对最稳定的 3-5 个主题，展示其规模（产品数）随时间变化。
- **产品归属稳定性评分**：列出跨期始终落在同一主题簇中的产品（“风格稳定”）。

#### 4.3.2 使用场景

- 观察某个投资主题是否持续强势；
- 识别周期性出现的主题（如季度末红利、科技轮动）；
- 评估某基金经理持仓风格是否稳定。

## 5. 对投资决策有参考意义的分析维度

### 5.1 主题级分析

| 分析 | 计算方法 | 投资含义 |
|---|---|---|
| **持续强势主题** | 连续两期以上存在、且成员平均收益排名前 30% 的簇 | 市场共识度高的方向，可作为核心配置参考 |
| **新兴主题** | 本期新增、规模较大（产品数 / 总权重）且收益靠前的簇 | 可能代表新主线启动 |
| **衰退主题** | 上期存在但本期消失，或规模显著缩小的簇 | 资金流出方向，需警惕 |
| **主题分化度** | 同一主题簇内成员收益的 standard deviation | 分化大说明主题内部选股差异大，或主题已扩散 |

### 5.2 产品级分析

| 分析 | 计算方法 | 投资含义 |
|---|---|---|
| **风格稳定产品** | 连续多期落在同一主题簇中，且距离质心较近 | 基金经理能力圈清晰，风格一致 |
| **风格漂移产品** | 频繁换簇，或从价值簇跳到成长簇 | 可能与招募说明书风格不符，或基金经理变更 |
| **提前布局产品** | 在上期属于小众簇/边缘成员，本期进入新兴主题核心簇 | 左侧交易能力强 |
| **跟随轮动产品** | 在本期从旧主题迁移到新兴主题，且收益靠前 | 趋势跟随能力强，但需判断可持续性 |

### 5.3 簇收益与风险分析

| 分析 | 计算方法 | 投资含义 |
|---|---|---|
| **簇收益持续性** | 同一簇在相邻两期之间的期间收益排名变化 | 判断主题是否有延续性 |
| **簇风险调整后收益** | 簇综合净值收益 / 簇内成员收益波动率 | 识别高风险低收益的主题 |
| **簇与市场 Beta** | 簇综合净值相对沪深300的回归 Beta | 判断主题防御/进攻属性 |
| **簇内选股 Alpha** | 使用 Brinson 归因，对比簇内产品相对簇平均的超额收益 | 识别簇内优秀/糟糕的产品 |

### 5.4 市场结构信号

| 分析 | 计算方法 | 投资含义 |
|---|---|---|
| **聚类数量增加** | k 值或实际簇数上升 | 市场风格分化，主题增多 |
| ** silhouette 下降** | 聚类质量下降 | 持仓结构趋同或混乱，市场可能处于切换期 |
| **AC 份额合并占比变化** | 同一产品家族合并后的权重占比变化 | 判断机构资金是否在集中布局 |

## 6. 前端交互设计建议

### 6.1 全局时间区段选择器

在 `/similarity` 页面顶部增加时间区段选择：

```
[开始日期] [结束日期] [应用]
```

- 默认开始日期 = 最新报告期前 90 天，结束日期 = 今天；
- 应用后，系统根据对齐规则决定进入单期或对比模式；
- 在结果区域明确提示“基于报告期：2026-03-31”或“对比报告期：2026-03-31 vs 2026-06-30”。

### 6.2 新增页面：聚类演化 `/similarity/evolution`

用于双期/多期对比，包含：

- 顶部：时间区段、有效报告期、模式切换按钮（单期 / 双期 / 时间轴）；
- 左侧：旧期簇列表；
- 右侧：新期簇列表；
- 中部：Sankey 流向图或矩阵表格，展示簇间成员流动；
- 下方：主题漂移、产品流动、收益分化三个 Tab。

### 6.3 单产品页增强

在现有 `/similarity/products/<id>` 页面基础上：

- 增加“归属时间轴”图表：每个报告期一个点，颜色代表所属主题；
- 增加“风格稳定性评分”：跨期归属一致性指标；
- 增加“最近一次换簇说明”：若产品从上期到本期换簇，提示旧主题 → 新主题，并列出驱动变化的重仓股/行业。

### 6.4 单簇页增强

在现有 `/similarity/<run_id>/cluster/<id>` 页面基础上：

- 增加“上期同源簇”入口：若该簇在上期有映射关系，提供链接跳转对比；
- 增加“成员变化”列表：新加入成员、离开成员、留守成员；
- 增加“主题一致性”指标：本期 top_industries 与上期同源簇的 Jaccard 相似度。

### 7.3 数据存储

- `similarity_cluster_mapping`：预计算相邻两期簇之间的映射关系（old_run_id, old_cluster_id, new_run_id, new_cluster_id, overlap_ratio, relationship）。

## 8. 推荐落地优先级

| 优先级 | 功能 | 说明 |
|---|---|---|
| P0 | 时间区段对齐与单期回退 | 解决用户问题 1，最小改动，直接复用现有单期页面。 |
| P0 | 双期对比页面（簇映射 + 成员流动） | 解决用户问题 2 的核心，投资价值最高。 |
| P1 | 主题漂移与产品流动分析 | 在双期对比页面中增加具体投资信号。 |
| P1 | 单产品归属时间轴 | 提升产品详情页价值，改动较小。 |
| P2 | 多期时间轴视图（3 期+） | 适合季度复盘，用户频次低于双期对比。 |
| P2 | 预计算 cluster_mapping 表 | 数据量大或报告期多时再做，前期可实时计算。 |
| P3 | 智能投资推荐（强势/新兴/衰退主题） | 基于前面能力做聚合封装，需产品化验证。 |

## 9. 示例用户流程

### 9.1 流程 A：区段内无更新

1. 用户选择 2026-04-01 ~ 2026-06-20；
2. 系统解析有效报告期为 [2026-03-31]；
3. 提示“该区段内无持仓更新，展示基于 2026-03-31 的聚类结果”；
4. 进入现有 `/similarity/<run_id>` 单期页面。

### 9.2 流程 B：跨报告期对比

1. 用户选择 2026-04-01 ~ 2026-07-10；
2. 系统解析有效报告期为 [2026-03-31, 2026-06-30]；
3. 提示“已进入 2026-03-31 vs 2026-06-30 双期对比模式”；
4. 进入 `/similarity/evolution` 页面；
5. 用户看到：
   - “科技成长”簇从 03-31 的 45 只产品变为 06-30 的 62 只，新增 18 只主要来自“消费电子”和“半导体”；
   - “红利价值”簇成员流失 12 只，其中 8 只进入“科技成长”；
   - 某产品从“消费复苏”簇迁移到“科技成长”簇， driven by 新增重仓 AI 芯片股。

### 9.3 流程 C：单产品风格诊断

1. 用户进入某产品详情页；
2. 看到归属时间轴：2025Q4 → 科技成长，2026Q1 → 科技成长，2026Q2 → 科技成长；
3. 风格稳定性评分 95/100，提示“风格稳定，核心能力圈在科技成长”。

## 10. 总结

多期持仓数据为聚类分析带来的最大价值不是“把多个报告期拼在一起聚类”，而是**观察聚类结果随时间的变化**。因此，前端不应强制用户只能看单一期，而应提供：

1. **时间区段智能对齐**：自动映射到有效报告期，无更新时回退到最近报告期；
2. **双期对比视图**：默认展示相邻两期聚类的簇映射、成员流动、主题漂移；
3. **多期时间轴视图**：支持季度级主题演化复盘；
4. **投资信号落地**：持续强势主题、新兴主题、风格稳定/漂移产品、簇收益分化等具体指标。

建议优先落地 P0 和 P1 功能，即可显著提升当前系统的投资分析价值。
