## 1. 背景与目标

### 1.1 业务价值

基于持仓的相似性量化评估，是理财产品研究、组合监控与智能推荐的基础设施。具体价值包括：

- **产品分类与画像**：按实际持仓特征对股票类基金聚类，识别行业偏好、配置偏好和主题属性。
- **基金经理能力比较**：对配置方向相近的产品做横向归因，识别同一市场方向下不同经理的选股与择时能力。
- **市场预期判断**：追踪聚类持仓的跨期行业迁移，捕捉市场主流资金对行业走势的共识变化。
- **替代标的推荐**：为限购、清盘或费率较高的产品寻找持仓结构相近的替代。
- **风险集中度监控**：识别持仓高度重叠的产品组合，提示单一标的/行业/发行人风险。

### 1.2 设计目标

1. **可解释**：每个聚类、相似度、归因分数都能追溯到具体持仓和行业贡献。
2. **分层可配**：支持个股、行业、大类资产、发行人、风格标签等多维度分析。
3. **服务独立**：与数据采集/处理解耦，形成可独立部署、CLI 可调用的服务。
4. **可扩展**：算法以 Python/NumPy 实现，预留稀疏矩阵与 ANN 索引加速能力。
5. **可落地**：优先基于当前已采集字段实现，对缺失数据给出明确补齐路径。

## 2. 需求约束与方案对齐

本次方案需同时满足以下三类目标：

| 目标 | 具体诉求 | 对应方案能力 |
|------|----------|--------------|
| **产品分类与画像** | 通过持仓特征对股票类基金分类，描述行业偏好、配置偏好 | **聚类层（Clustering）+ 画像层（Profiling）** |
| **横向比较操作能力** | 配置类似产品的市值变化对比，识别基金经理微观操作优劣 | **归因层（Attribution）**：Brinson 归因 + 同簇排名 |
| **判断市场预期** | 通过聚类持仓变化观察行业增减仓 | **迁移层（Shift）**：跨期聚类对齐 + 行业增减仓聚合 |

此外，用户明确要求：

- **数据周期**：季度更新前十大持仓，交易日更新持仓市值。
- **部署形态**：与采集处理相对独立的服务，可被 CLI/Agent 调用。

**总体判断**：传统“两两相似度 + Top-N 推荐”不足以完整支撑上述目标。本方案将原 pairwise 相似度能力保留为辅助模块，同时新增 **聚类、归因、迁移** 三大核心能力，并以独立服务形式封装。

## 5. 核心算法设计

### 5.1 相似度层

用于 pairwise 比较与辅助聚类。三种经典指标：

| 指标 | 公式 | 特点 |
|------|------|------|
| **Overlap Coefficient** | \(S_O(A,B)=\sum_k \min(w_{A,k}, w_{B,k})\) | 直接反映共同持仓权重重合，业务解释性最强，**默认主指标** |
| **Cosine Similarity** | \(S_C(A,B)=\frac{\sum_k w_{A,k} w_{B,k}}{\|w_A\| \|w_B\|}\) | 学术常用，对高权重共同标的敏感 |
| **Jaccard Index** | \(S_J(A,B)=\frac{|A \cap B|}{|A \cup B|}\) | 仅看标的是否相同，忽略权重 |

其中 \(w_{A,k}\) 表示产品 A 在资产 k 上的占净值比（未持仓为 0）。

### 5.2 聚类层

#### 5.2.1 特征矩阵

| 阶段 | 特征空间 | 维度 | 说明 |
|------|----------|------|------|
| 短期（当前） | 产品 × 个股权重 | 高维、稀疏 | 无需额外数据即可启动 |
| 中期（推荐） | 产品 × 行业权重 | 20–40 维 | 需补齐行业映射，可解释性强 |
| 长期 | 产品 × （行业 + 风格 + 大类资产） | 中维 | 最稳定的聚类输入 |

#### 5.2.2 算法选型

| 算法 | 适用场景 | 推荐度 |
|------|----------|--------|
| **K-Means++** | 有行业/风格特征后做可解释聚类 | ⭐⭐⭐ 主算法 |
| **K-Means on 个股向量** | 当前无行业数据时的过渡方案 | ⭐⭐⭐ 当前可用 |
| **层次聚类** | 生成基金谱系，便于可视化 | ⭐⭐ 辅助 |
| **谱聚类 / 社区发现** | 发现非球形主题簇 | ⭐⭐ 进阶 |

#### 5.2.3 选 K 策略

- 肘部法则（SSE 拐点）
- Silhouette Score
- 业务可解释性校验：确保每个簇都有清晰标签（如“光通信主题”、“大盘蓝筹均衡”）

#### 5.2.4 簇画像输出

对每个簇自动生成：

- **Top 5 行业及平均权重**（依赖行业映射）
- **Top 10 代表性重仓股**
- **平均集中度**（HHI）
- **机构/基金经理分布**
- **代表产品列表**
- **簇内平均相似度**

### 5.3 归因层

采用 **Brinson 模型**，将产品相对基准的超额收益分解为：

\[
\text{配置贡献 AR} = \sum_i (w_{p,i} - w_{b,i}) \cdot r_{b,i}
\]

\[
\text{选股贡献 SR} = \sum_i w_{b,i} \cdot (r_{p,i} - r_{b,i})
\]

\[
\text{交互贡献 IR} = \sum_i (w_{p,i} - w_{b,i}) \cdot (r_{p,i} - r_{b,i})
\]

其中 \(i\) 为行业，基准 \(b\) 支持两种选择：

- **同簇平均组合（默认）**：取同簇所有产品的行业权重均值作为基准权重，取同簇在该行业的整体收益作为基准收益。该基准直接回答“同一市场方向下，谁的仓位更重、谁的个股选择更好”。
- **宽基指数（沪深 300 / 中证 800）**：从中证指数公司下载指数成分股权重，将成分股按行业聚合为指数行业权重与收益。该基准用于评估产品相对市场基准的绝对能力，便于识别“跑赢了大盘但跑输了同簇”或“同簇均不佳但相对大盘仍领先”的情况。

当前实现以**行业维度 Brinson**为主：
1. 用 `market_quote` 中的个股日行情计算区间内各股票简单收益率。
2. 将个股收益按产品持仓权重聚合为产品-行业收益；将同簇持仓聚合为簇-行业基准收益。
3. 缺失行情的股票在组合与基准中同步剔除并按剩余权重归一化；产品未配置的行业其行业收益视为基准收益，保证配置效应独立衡量行业偏离，选股效应只反映有持仓行业的个股选择。

### 5.4 迁移层

用于推断市场预期：

1. 对相邻两个报告期分别聚类。
2. 计算每个簇的行业权重变化：
   \[
   \Delta w_{c,i} = w_{c,i}^{(t)} - w_{c,i}^{(t-1)}
   \]
3. 聚合所有簇的行业增减仓：
   - 加仓 Top N 行业 → 市场预期向好
   - 减仓 Top N 行业 → 市场预期走弱
4. 识别“共识行业”：多个簇同时加仓/减仓的行业，代表市场整体预期。
5. 输出聚类行业迁移热力图和文字摘要。

## 6. 特征工程与数据补齐

### 6.1 A/C 份额处理

同一产品 A/C 份额持仓几乎一致，会污染聚类和横向比较。处理策略：

1. **聚类前合并**：先按产品名称去掉尾部 A/B/C/E/H 份额后缀得到基础名；同一机构、同一基础名下的产品作为候选组。为避免把“XX基金”和“XX基金A”等无关产品错误归并，**仅当候选组内至少有两个产品带有明确的份额后缀时才执行合并**。合并时保留持仓数量最多的那只（通常是 A 份额或主份额），并记录 `merge_map` 用于后续画像。
2. **归因时去重**：同一 `product_code` 多只份额只保留一只参与排名。
3. **画像标注**：在 `ClusterProfile` 中输出 `ac_share_dominance_ratio`；若该比值高，提示“该簇主要为同产品不同份额”。

### 6.2 数据补齐优先级

| 数据 | 优先级 | 来源建议 |
|------|--------|----------|
| 个股行业映射 | ⭐⭐⭐⭐⭐ | `HoldingSecurityInfo` 补充申万/中信行业；AKShare `stock_industry_classification_em` |
| 个股日行情 | ⭐⭐⭐⭐⭐ | Eastmoney K-line（复用 ``MarketQuoteCollector`` 逻辑）<br>AKShare `stock_zh_a_hist_em` 可作为备选 |
| 行业指数行情 | ⭐⭐⭐⭐ | AKShare `index_zh_a_hist_em` |
| 债券持仓 | ⭐⭐⭐ | 天天基金 F10 债券持仓接口 |
| 大类资产配置 | ⭐⭐⭐ | 天天基金 F10 资产配置接口 |
| 多期持仓 | ⭐⭐⭐ | 持续采集 `holding_report` |

### 6.3 特征归一化

- 对个股权重向量做 L2 归一化，降低持仓集中度差异对聚类的过度影响。
- 对行业权重向量直接使用原始权重，便于解释。
- 对跨市场资产（A 股、港股、美股）可分开或统一编码。

## 7. 数据模型与存储

### 7.1 新增结果表

#### `similarity_cluster_run` —— 聚类运行批次

```sql
CREATE TABLE similarity_cluster_run (
    id BIGSERIAL PRIMARY KEY,
    report_date DATE NOT NULL,
    product_type_filter VARCHAR(100),  -- equity,mixed
    algorithm VARCHAR(30) NOT NULL DEFAULT 'kmeans',
    k INT NOT NULL,
    params_json JSONB,                 -- 运行参数，用于复现
    silhouette DECIMAL(10, 6),
    inertia DECIMAL(20, 6),
    n_products INT,
    n_features INT,
    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    UNIQUE (report_date, algorithm, k, product_type_filter, created_at)
);
```

#### `similarity_clusters` —— 聚类结果

```sql
CREATE TABLE similarity_clusters (
    id BIGSERIAL PRIMARY KEY,
    cluster_run_id BIGINT NOT NULL REFERENCES similarity_cluster_run(id) ON DELETE CASCADE,
    report_date DATE NOT NULL,
    product_type_filter VARCHAR(100),  -- equity,mixed
    algorithm VARCHAR(30) NOT NULL DEFAULT 'kmeans',
    k INT NOT NULL,
    cluster_id INT NOT NULL,
    cluster_label VARCHAR(100),        -- 自动标签，由 derive_cluster_label(top_industries) 生成，如“通信设备 + 半导体 + 元件”；可人工覆盖
    size INT NOT NULL,
    top_industries JSONB,              -- [{industry, weight}]
    top_holdings JSONB,                -- [{asset_code, asset_name, weight}]
    avg_hhi DECIMAL(10, 6),
    avg_overlap DECIMAL(10, 6),        -- 基于 L2 归一化向量
    avg_overlap_raw DECIMAL(10, 6),    -- 基于原始权重
    ac_share_dominance_ratio DECIMAL(10, 6),
    institution_distribution JSONB,    -- {institution_code: count}
    representative_products JSONB,     -- [product_id]
    representative_codes JSONB,        -- [product_code]
    representative_names JSONB,        -- [product_name]
    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    UNIQUE (cluster_run_id, cluster_id)
);
```

#### `similarity_cluster_members` —— 聚类成员关系

```sql
CREATE TABLE similarity_cluster_members (
    id BIGSERIAL PRIMARY KEY,
    report_date DATE NOT NULL,
    cluster_run_id BIGINT NOT NULL REFERENCES similarity_cluster_run(id) ON DELETE CASCADE,
    product_id BIGINT NOT NULL REFERENCES product_info(id) ON DELETE CASCADE,
    cluster_id INT NOT NULL,
    distance_to_center DECIMAL(10, 6),
    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    UNIQUE (report_date, product_id, cluster_run_id)
);
```

#### `index_constituent_weight` —— 指数成分股权重（新增强基指数基准）

```sql
CREATE TABLE index_constituent_weight (
    id BIGSERIAL PRIMARY KEY,
    index_code VARCHAR(20) NOT NULL,        -- 000300 / 000906
    index_name VARCHAR(100),
    constituent_code VARCHAR(20) NOT NULL,  -- 成分股代码
    constituent_name VARCHAR(100),
    market VARCHAR(10),                     -- SH / SZ / BJ
    weight DECIMAL(12, 6) NOT NULL,         -- 成分股权重（% 或小数，按源数据）
    effective_date DATE NOT NULL,
    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    UNIQUE (index_code, constituent_code, effective_date)
);
```

#### `similarity_attribution` —— Brinson 归因结果

```sql
CREATE TABLE similarity_attribution (
    id BIGSERIAL PRIMARY KEY,
    product_id BIGINT NOT NULL REFERENCES product_info(id) ON DELETE CASCADE,
    cluster_run_id BIGINT NOT NULL REFERENCES similarity_cluster_run(id) ON DELETE CASCADE,
    cluster_id INT NOT NULL,
    report_date DATE NOT NULL,
    start_date DATE NOT NULL,
    end_date DATE NOT NULL,
    benchmark_type VARCHAR(30) NOT NULL,  -- index / cluster_avg

    total_return DECIMAL(10, 6),
    benchmark_return DECIMAL(10, 6),

    allocation_effect DECIMAL(10, 6),
    selection_effect DECIMAL(10, 6),
    interaction_effect DECIMAL(10, 6),

```

#### `similarity_shift` —— 跨期行业迁移

```sql
CREATE TABLE similarity_shift (
    id BIGSERIAL PRIMARY KEY,
    report_date_a DATE NOT NULL,
    report_date_b DATE NOT NULL,
    industry_name VARCHAR(100) NOT NULL,
    delta_weight DECIMAL(10, 6),
    cluster_consensus_score DECIMAL(10, 6),  -- 多个簇同时加仓的程度
    direction VARCHAR(10),                   -- increase / decrease
    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    UNIQUE (report_date_a, report_date_b, industry_name)
);
```

#### `product_similarity` —— pairwise 相似度（可选，用于推荐）

保留原方案设计，但仅对高相似 pair 或 Top-K 写入，控制存储量。

```sql
CREATE TABLE product_similarity (
    id BIGSERIAL PRIMARY KEY,
    product_a_id BIGINT NOT NULL REFERENCES product_info(id) ON DELETE CASCADE,
    product_b_id BIGINT NOT NULL REFERENCES product_info(id) ON DELETE CASCADE,
    report_date_a DATE NOT NULL,
    report_date_b DATE NOT NULL,
    stock_overlap DECIMAL(10, 6),
    stock_cosine DECIMAL(10, 6),
    stock_jaccard DECIMAL(10, 6),
    industry_overlap DECIMAL(10, 6),
    asset_class_overlap DECIMAL(10, 6),
    issuer_overlap DECIMAL(10, 6),
    total_similarity DECIMAL(10, 6),
    algorithm_version VARCHAR(30) NOT NULL DEFAULT 'v1',
    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    UNIQUE (product_a_id, product_b_id, report_date_a, report_date_b, algorithm_version)
);
```

### 7.2 结果表设计原则

- 所有结果表以 `similarity_` 为前缀，与采集表隔离。
- 支持按 `report_date`、`algorithm`、`k` 多版本共存，便于回溯。
- 归因表支持按指数基准和同簇基准分别存储。

## 10. 风险、局限与后续优化

### 10.1 数据风险

| 风险 | 说明 | 缓解措施 |
|------|------|----------|
| 持仓披露不完整 | 当前仅前十大股票 | 结果标注“基于前十大持仓”；逐步接入完整持仓 |
| 行业映射缺失 | `industry_name` 为空 | 优先补充行业字典；缺失时降级为个股维度 |
| 个股行情缺失 | 已补齐个股日行情，可支撑归因窗口 | 持续接入行情，保证交易日更新 |
| 多期数据不足 | 当前仅 2026Q1 | 随季度采集推进逐步启用迁移分析 |
| 债券/基金持仓缺失 | 固收类产品无法有效聚类 | 对银行理财以大类资产和行业维度为主 |

### 10.2 算法风险

- **AC 份额重复**：已设计合并策略。
- **主簇过大**：高维稀疏导致大量均衡产品落入同一簇；引入行业/风格特征后可显著改善。
- **指数基金同质化**：同一指数产品持仓高度一致，聚类时会自然成簇，需在画像中标注“指数跟踪型”。
- **报告期滞后**：归因和迁移分析结果反映的是过去季度末截面，非实时观点。

### 10.3 性能风险

- 全量 pairwise 相似度计算复杂度 \(O(N^2 \cdot K)\)。当前 4,200 只有持仓产品约 880 万对，可接受；随规模增长需预计算 + ANN 索引。
- 聚类特征矩阵高维稀疏，需使用 `scipy.sparse` 或 `numpy` 稀疏表示。

### 10.4 后续优化方向

1. 结合净值收益相关性构建多维度相似性（净值 + 持仓）。
2. 引入 Barra 多因子模型做风格归因。
3. 使用 LLM 自动为聚类簇生成中文标签与解读。
4. 构建产品持仓向量索引，支持实时最近邻搜索。
