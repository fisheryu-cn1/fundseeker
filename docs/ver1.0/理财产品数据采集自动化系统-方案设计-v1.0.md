# 理财产品数据采集自动化系统——具体方案设计

> 基于 `Proposal/理财产品统一数据采集方案报告.md` 与 `Proposal/理财产品信息来源清单与采集规范.md` 的初步设想，本文档给出可直接落地的第一阶段实施方案。

---

## 1. 目标与范围

### 1.1 本期目标
建立一个可自动定时执行的理财产品数据采集与整理程序，满足：
- 以**公募基金公司**与**银行理财子公司**的核心公开信息为采集对象
- 支持**产品列表、净值、收益率、公告、费率**等关键字段的统一存储
- 数据持久化到专用目录 `/data/fundseeker`
- 使用系统已有组件（Docker、cron、Python）最小成本落地，避免引入过重中间件

### 1.2 首批试点机构（P0）
| 机构 | 类型 | 代码 | 主要数据来源 |
|------|------|------|-------------|
| 易方达基金 | 公募基金公司 | YFD | 官网列表页 + 天天基金网详情 |
| 汇添富基金 | 公募基金公司 | HTF | 官网列表页 + 天天基金网详情 |
| 招银理财 | 银行理财子 | ZY | 官网公募产品页 + 产品说明书 |
| 建信理财 | 银行理财子 | JX | 官网产品列表 + 产品说明书 |

后续按阶段扩展至报告清单中全部 61 家机构。

## 3. 数据存储设计

### 3.1 数据库选型：本地 PostgreSQL 16 服务

当前系统已安装非 Docker 的本地 PostgreSQL 16，数据目录位于 `/data/postgresql`，配置文件位于 `/etc/postgresql/16/main/`。该服务此前处于停止状态，现已通过以下命令启动：

```bash
systemctl start postgresql.service
systemctl start postgresql@16-main
```

**关键连接信息**：

| 项目 | 值 |
|------|-----|
| 端口 | `5433`（非默认 5432） |
| 数据目录 | `/data/postgresql` |
| 可用用户 | `cc`（Superuser） |
| 已创建数据库 | `fundseeker` |
| 推荐连接方式 | Unix socket（免密码） |

**连接示例**：

```bash
# Unix socket（推荐，无需密码）
psql -h /var/run/postgresql -p 5433 -U cc -d fundseeker

# SQLAlchemy 连接字符串
postgresql+psycopg2://user:password@localhost:5432/fundseeker
```

> 注：通过 `localhost:5433` 连接需要密码；程序内部统一使用 Unix socket 连接以简化认证。

## 4. 采集模块设计

### 4.1 采集策略

| 数据类型 | 频率 | 时间窗口 | 说明 |
|---------|------|---------|------|
| 产品列表 | 每日 | 06:00-08:00 | 发现新增/下架/状态变更 |
| 净值数据 | 每日(T+1) | 21:00-23:00 | 晚间披露前一日净值 |
| 收益率数据 | 每日 | 随净值一起 | 列表页展示的收益率为最新快照 |
| 公告信息 | 每日 | 08:00-09:00 | 新增公告检查 |
| 基本信息 | 每周 | 周日 02:00 | 复核管理人、费率等低频变更字段 |
| 费率信息 | 每月 | 每月1日 03:00 | 费率调整跟踪 |
| 持仓/规模 | 每季度 | 季报披露后次日 | 跟随定期报告周期 |

### 4.2 采集器实现

每个机构实现一个 `Collector` 类，统一接口：

```python
class BaseCollector(ABC):
    @abstractmethod
    def collect_product_list(self) -> list[dict]: ...

    @abstractmethod
    def collect_nav(self, product_code: str) -> list[dict]: ...

    @abstractmethod
    def collect_announcements(self, product_code: str) -> list[dict]: ...
```

#### 4.2.1 公募基金公司（易方达、汇添富）

- **列表页**：使用 `requests/httpx` 请求官网产品列表页，BeautifulSoup/lxml 解析
- **详情页**：优先调用天天基金网公开接口（如 `fundf10.eastmoney.com`）获取完整档案
- **反爬处理**：单 IP 请求间隔 ≥ 5 秒；设置合理 User-Agent

#### 4.2.2 银行理财子（招银理财、建信理财）

- **列表页**：官网产品列表页抓取
- **动态页面**：若 Vue/React 渲染导致静态抓取失败，使用 Playwright 启动 headless Chromium
- **说明书**：下载 PDF 后使用 `pdfplumber` 提取关键字段

### 4.3 数据清洗与标准化

清洗流程：
1. **字段映射**：将各机构原始字段映射到统一字段
2. **类型转换**：数值、日期标准化
3. **风险等级统一**：R1/PR1/低风险 → L1，以此类推
4. **产品类型统一**：股票型/权益类 → equity，债券型/固定收益类 → fixed_income
5. **去重与合并**：同一产品同一采集日仅保留一条快照
6. **校验**：
   - 核心字段非空（product_code、product_name、product_type、risk_level_standard）
   - 净值日期应为最近交易日
   - 收益率在合理范围（-50% ~ +100%）

### 4.4 市场行情数据采集

采集对理财产品分析具有参考价值的全球主要市场行情，每日最多记录一次。

| 市场/品种 | 内部代码 | 数据源 | 数据范围 | 历史数据支持 |
|----------|---------|--------|---------|------------|
| 上证指数 | SH000001 | 东方财富日K线 | 开/高/低/收/成交量/成交额 | ✅ 支持指定日期 |
| 深证成指 | SZ399001 | 东方财富日K线 | 开/高/低/收/成交量/成交额 | ✅ 支持指定日期 |
| 创业板指 | SZ399006 | 东方财富日K线 | 开/高/低/收/成交量/成交额 | ✅ 支持指定日期 |
| 沪深300 | SH000300 | 东方财富日K线 | 开/高/低/收/成交量/成交额 | ✅ 支持指定日期 |
| 恒生指数 | HSI | 东方财富日K线 | 开/高/低/收/成交量/成交额 | ✅ 支持指定日期 |
| 道琼斯工业指数 | DJIA | 东方财富日K线 | 开/高/低/收/成交量 | ✅ 支持指定日期 |
| 纳斯达克指数 | NDX | 东方财富日K线 | 开/高/低/收/成交量 | ✅ 支持指定日期 |
| 标普500指数 | SPX | 东方财富日K线 | 开/高/低/收/成交量 | ✅ 支持指定日期 |
| 布伦特原油 | BRENT_OIL | 新浪财经国际期货实时行情 | 最新价/开盘价/最高价/最低价/昨结算 | 仅当前交易日 |
| 纽约黄金 | GOLD | 新浪财经国际期货实时行情 | 最新价/开盘价/最高价/最低价/昨结算 | 仅当前交易日 |

采集逻辑：

- **指数**：通过东方财富 `push2his.eastmoney.com/api/qt/stock/kline/get` 按日K线获取；未指定日期时取最近一个交易日的数据，指定日期时精确拉取该日K线。
- **大宗商品**：通过新浪财经 `hq.sinajs.cn/list=hf_OIL,hf_GC` 获取实时行情；记录行情日期为数据源返回的本地交易日，暂不支持历史日期回溯。
- **成交量单位**：按数据源实际口径记录，避免呈现时混淆。
  - 沪深指数（`SH000001 / SZ399001 / SZ399006 / SH000300`）：东方财富返回的成交量单位为 **手**，`volume_unit = lot`。
  - 港股、美股指数（`HSI / DJIA / NDX / SPX`）：东方财富返回的成交量单位为 **股**，`volume_unit = share`。
  - 大宗商品（`BRENT_OIL / GOLD`）：新浪财经未提供成交量；如后续接入期货合约数据，单位统一记为 **合约/手**，`volume_unit = contract`。
- **去重**：数据库层通过 `market_quote(quote_date, symbol_code)` 唯一约束保证同一品种同一天只保留一条记录；运行层在任务启动前检查目标日期是否已存在全部品种，存在则跳过网络请求。
- **入口**：统一 CLI 提供 `--market-quotes` 和 `--market-date YYYY-MM-DD`，并纳入 `--all` 默认每日采集流程。

## 5. 调度与自动化

### 5.1 调度方式：cron

当前系统 `cron.service` 已运行，直接使用 cron 调度，无需额外引入 Airflow。

建议 crontab 配置：

```cron
# 每日早上 07:00 采集产品列表
0 7 * * * /home/cc/projects/fundseeker/scripts/fundseeker_daily.sh list

# 每日晚上 21:30 采集净值与收益率
30 21 * * * /home/cc/projects/fundseeker/scripts/fundseeker_daily.sh nav

# 每日早上 08:30 采集公告
30 8 * * * /home/cc/projects/fundseeker/scripts/fundseeker_daily.sh announcement

# 每周日 02:00 复核基本信息与费率
0 2 * * 0 /home/cc/projects/fundseeker/scripts/fundseeker_weekly.sh
```

### 5.2 任务脚本

- `scripts/fundseeker_daily.sh`：按数据类型触发采集
- `scripts/fundseeker_weekly.sh`：触发基本信息与费率复核
- 所有脚本输出重定向到 `/data/fundseeker/logs/fundseeker_YYYY-MM-DD.log`
