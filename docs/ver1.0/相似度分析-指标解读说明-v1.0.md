# Fundseeker 相似度分析指标解读说明

> 范围：聚类运行 / 簇详情 / 簇成员净值表现 3 个层级页面中所有展示指标的定义、计算方式与判读经验。
> 计算位置：除特殊说明外，所有指标均在聚类运行时由 [`src/fundseeker/similarity/profiling.py`](../src/fundseeker/similarity/profiling.py) 计算并持久化到 `similarity_cluster` 表；前端仅做读取与展示。簇标签 `cluster_label` 由 [`src/fundseeker/similarity/labels.py`](../src/fundseeker/similarity/labels.py) 生成。

---

## 0. 三层指标总览

| 层级 | 页面 | 指标 |
|---|---|---|
| 聚类运行级 | `similarity_index.html` / `similarity_compare.html` | k、产品数、特征维度、Silhouette、Inertia (SSE) |
| 簇级 | `similarity_run.html` 簇概览表 + `similarity_cluster.html` Header | 簇规模、Top 行业、Top 持仓、机构分布、HHI、Overlap、AC 份额合并占比、代表产品 |
| 簇内净值表现级 | `similarity_cluster.html` KPI 条 + Top5/Bottom5 + 综合净值曲线 | 平均涨跌幅、标准差、中位数、最大/最小、正收益占比、极差、变异系数、跨度天数、复合基准 |

下面按层级逐一解释。

---

## 1. 聚类运行级指标

### 1.1 `k`

- **含义**：聚类数目（簇数），即 K-Means 算法的目标簇数。
- **来源**：`similarity_cluster_run.k` 列；由聚类 CLI 参数 `--k` 或自动选择（`--k auto` 通过 silhouette 搜索）决定。
- **判读**：k 越大，每簇越细，单簇内产品同质性越高但规模越小；k 太小则可能把不同策略混在一起。建议结合 silhouette 综合判断。

### 1.2 `n_products`（参与产品数）

- **含义**：本次聚类实际参与的产品数量。
- **来源**：`similarity_cluster_run.n_products`。
- **判读**：反映了当次聚类的输入规模。注意：相同 `(institution_code, product_code)` 的 A/C 份额产品会先被合并（A/C 份额合并占比 > 0 时），所以 n_products 是「合并后的产品数」，不代表"原本有多少申赎单元"。

### 1.3 `n_features`（特征维度）

- **含义**：聚类使用的特征维度数。
  - 当 `feature_type=asset` 时 = 持仓证券代码去重后的总数
  - 当 `feature_type=industry` 时 = 行业类别数
- **来源**：`similarity_cluster_run.n_features`。
- **判读**：维度越高说明输入数据越丰富；但 K-Means 在高维空间会受"维度诅咒"影响，silhouette 通常会偏低。

### 1.4 `Silhouette`（轮廓系数）

- **含义**：衡量簇内紧密度 vs 簇间分离度。
- **计算**：对每个样本 i，`s(i) = (b(i) − a(i)) / max(a(i), b(i))`，其中 `a(i)` 是 i 到同簇其他点的平均距离，`b(i)` 是 i 到最近邻簇所有点的平均距离。簇的 silhouette 是所有样本 s(i) 的均值。
- **取值范围**：`-1 ~ 1`
  - `≈ 1`：簇内紧致、簇间分离，**聚类质量好**
  - `≈ 0`：样本位于两簇边界
  - `< 0`：样本可能被分到了错误的簇
- **来源**：`similarity_cluster_run.silhouette` 列；K-Means 在训练时计算。

### 1.5 `Inertia`（簇内平方和 / SSE）

- **含义**：所有样本到其所在簇质心的欧氏距离平方和。
- **计算**：`Σ_i ‖x_i − centroid[label[i]]‖²`
- **判读**：
  - 数值越小表示簇内越紧凑
  - 单看绝对值意义不大；通常用于**跨 k 对比**：同一个数据集上 Inertia 随 k 单调递减，下降速度变缓的拐点对应「最优 k」
  - `similarity_run.html` 中的「跨运行 Inertia 对比」气泡图就是把多组 (algorithm, k) 的 (k, Inertia) 放在同一张图上找拐点

### 1.6 `report_date`（报告期）

- **含义**：本次聚类使用的持仓快照日期。
- **业务定义**：报告期 = 最新 `product_holding.report_date`，**不是**系统当前日期。
- **判读**：报告期距今多久，反映聚类结论的「时效性」。当前 DB 报告期 = 2026-03-31，因为持仓数据每季度发布一次，3.5 个月的滞后属于业务节奏。

## 2. 簇级指标（`similarity_run.html` 概览表 + `similarity_cluster.html` Header）

### 2.1 `size`（簇规模）

- **含义**：簇内产品数量（K-Means 实际看到的样本数，A/C 份额合并后的）。
- **判读**：极小簇（如 size < 5）通常意味着产品特征独特、缺乏同伴；过大簇（size > 总样本 × 0.4）往往意味着聚类欠拟合，应增大 k。

### 2.2 `top_industries`（Top 行业）

- **含义**：簇质心按行业聚合后权重最大的前 N 个行业。
- **计算**（[profiling.py:54-76](../src/fundseeker/similarity/profiling.py#L54-L76)）：
  ```
  对簇质心每个维度 i：
    industry_weights[mapping.get(asset_code_i, market_i)] += centroid[i]
  按行业权重降序取前 top_n_industries (=5) 个
  ```
- **判读**：是「簇投资主题」的可读化输出，被 `derive_cluster_label()`（实现见 [`src/fundseeker/similarity/labels.py`](../src/fundseeker/similarity/labels.py)）用于生成簇名（如"电池 + 半导体 + 通信设备"）。权重越大代表簇越偏向该行业。

### 2.3 `cluster_label`（簇标签）

- **含义**：根据 `top_industries` 自动生成的可读标签，用于在页面标题、簇概览表中快速识别簇主题。
- **计算**：`derive_cluster_label(top_industries)`：取权重 ≥ 5% 的行业，去掉「Ⅱ/III/II/I/1/2/3」等后缀，去重后取前 3 个，用「 + 」连接。
- **来源**：`similarity_cluster.cluster_label`，由 `ClusterProfile.build_profiles()` 生成并通过 `save_cluster_run()` 持久化。
- **判读**：如「通信设备 + 半导体 + 元件」「白酒 + 白色家电 + 摩托车及其他」。web 层优先读取持久化值，缺失时回退到路由层重新派生。

### 2.4 `top_holdings`（Top 持仓）

- **含义**：簇质心中权重最大的前 N 个资产（默认 10）。
- **来源**：当 `feature_type=asset` 时直接取质心 top-10；为 `industry` 时取行业 top-10 并标记为 `asset:行业名`。
- **判读**：可读出"该簇在重仓哪些具体股票/债券"。

### 2.5 `institution_distribution`（机构分布）

- **含义**：`{institution_code: 该机构在簇内的产品数}`。
- **判读**：单家机构占比 > 50% 提示「产品线内部策略趋同」；多家机构均匀分布提示「跨机构共同策略」。

### 2.6 平均 HHI（**Herfindahl-Hirschman Index**）

- **定义**（[features.py:210-212](../src/fundseeker/similarity/features.py#L210-L212)）：
  ```
  HHI(p) = Σ_i w_i²    # p 的所有持仓权重平方和
  avg_hhi = mean([HHI(p) for p in 簇内产品])
  ```
- **取值范围**：1/N（完全分散）~ 1（全部压在一只持仓上）
- **为什么用 `raw_weights` 而非归一化向量**：归一化后抹掉了绝对规模，"重仓茅台 30%" 和 "重仓茅台 5%" 形状一样但集中度天差地别。用原始权重才能反映真实集中度。
- **判读经验值**：

  | avg_hhi | 含义 |
  |---|---|
  | `< 0.05` | 极度分散（典型指数基金） |
  | `0.05 ~ 0.15` | 分散持仓 |
  | `0.15 ~ 0.30` | 中度集中（有重点品种） |
  | `> 0.30` | 高度集中（重仓少数） |

### 2.7 平均 Overlap（**Overlap Coefficient**）

- **定义**（[profiling.py:34-51](../src/fundseeker/similarity/profiling.py#L34-L51)）：
  ```
  overlap(p, q) = Σ_k min(w_p,k, w_q,k)
  cluster_overlap = 所有产品对 overlap 的均值
  ```
- **两种语义**（UI 同时展示两列）：

  | 字段 | 输入 | 语义 |
  |---|---|---|
  | `avg_overlap`（归一化） | L2 归一化后的向量 | 几何形状相似度 —— 反映聚类算法"看到"的相似性 |
  | `avg_overlap_raw`（原始权重） | 原始权重向量 | 业务直觉的"共同持仓" —— 反映真实仓位重合度 |

- **取值范围**：0 ~ 1
- **判读经验值**：

  | avg_overlap | 含义 |
  |---|---|
  | `< 0.10` | 簇内产品持仓几乎不重合 |
  | `0.10 ~ 0.30` | 部分重合（有共同主战场） |
  | `0.30 ~ 0.60` | 高度重合（同策略复制） |
  | `> 0.60` | 几乎雷同（同模板发行） |

### 2.8 AC 份额合并占比（`ac_share_dominance_ratio`）

- **背景**：A/C 份额是同一只母基金的费率差异化子份额（名称如「基金A」「基金C」），持仓完全相同。聚类前需要先合并，否则同一策略会被误拆成多个簇。
- **合并规则**（[features.py:81-142](../src/fundseeker/similarity/features.py#L81-L142)）：按 `(institution_code, 基础名)` 分组，组内**至少 2 个**带显式份额后缀（A/B/C/E/H 等）时才合并；保留 holding 数量最多的那个为「母份额」。
- **指标计算**（[profiling.py:165-178](../src/fundseeker/similarity/profiling.py#L165-L178)）：
  ```
  total_merged = Σ 簇内每个 kept product 在 merge_map 中关联的 product_id 数（含自身）
  ratio = (total_merged − size) / size
  ```
- **判读**：

  | ratio | 含义 |
  |---|---|
  | `= 0` | 簇内无 A/C 合并；所有产品都"独立" |
  | `> 0` | 部分产品来自 A/C 份额拆分；值越大合并越密集 |
  | `≥ 1` | 平均每个 kept product 至少带 1 个兄弟份额 |

- **业务意义**：当 ratio > 0 时，UI 显示的"簇规模 100"实际代表 `100 × (1 + ratio)` 份独立申赎单元，但因投资策略完全相同被折算成 100 个样本参与聚类。这是为了避免同一发行人按费率发行多份"假不同"产品被分散到不同簇。

### 2.9 `representative_products` / `representative_codes` / `representative_names`（代表产品）

- **含义**：簇内**最接近质心**的最多 5 个产品（`max_representatives=5`）。
- **计算**（[profiling.py:181-186](../src/fundseeker/similarity/profiling.py#L181-L186)）：
  ```
  dist_to_center = ‖x_i − centroid‖₂
  rep = argsort(dist_to_center)[:5]
  ```
- **判读**：代表产品是该簇的"标准动作"，可以作为深入查看某个簇的入口。

### 2.10 三者协同判读

HHI、Overlap、AC 合并占比一起回答「簇内成员长得有多像」：

| 指标 | 问的是 | 数值高意味着 |
|---|---|---|
| HHI | 单只产品**自身**的持仓有多集中 | 押注型产品（主题/行业基金） |
| Overlap | 簇内成员**两两之间**的持仓重合度 | 同策略发行 / 复制型产品群 |
| AC 份额合并占比 | 簇内有多少产品来自同一份母基金的份额拆分 | 同发行人、仅按费率发行的"假不同"产品 |

例：`HHI=0.32, avg_overlap=0.45, AC=0.20` → "重仓型策略组，簇内产品持仓相似度高，约 20% 的样本来自同一只母基金的 A/C 份额拆分。"

## 3. 簇内净值表现级指标（`similarity_cluster.html`）

这部分所有指标都基于「**簇内每个产品的区间涨跌幅**」（`period_change_pct`），按产品的**逻辑产品键** `(institution_code, product_code)` 聚合所有兄弟 `product_id` 的 `product_nav` 记录计算。窗口为 `[today-1-days, today-1]`（市场行情 1 天滞后）。

### 3.1 `period_change_pct`（区间涨跌幅）

- **定义**：
  ```
  period_change_pct(p) = (latest_nav(p) − earliest_nav(p)) / earliest_nav(p)
  ```
  其中 `earliest_nav` 是产品在窗口内**最早**日期的 NAV，`latest_nav` 是窗口内**最晚**日期的 NAV。
- **判读**：
  - 单条产品必须有 ≥ 2 条落在窗口内的 NAV 才有值；只有 1 条的产品返回 `None`，被排除在 Top5/Bottom5 之外。
  - 当数据库 NAV 不足时（如采集稀疏期），统计指标会降级或为空，UI 显示 `—`。

### 3.2 `span_days`（数据跨度）

- **定义**：`latest_nav_date − earliest_nav_date`（按天）。
- **判读**：与"行情窗口"不一定相等 —— `span_days` 反映的是实际取到的最早-最晚 NAV 日期差。如果数据库 NAV 不足，可能短于用户选定的 days。

### 3.3 KPI 条卡指标

#### 3.3.1 `平均涨跌幅`（`dispersion.mean_change`）

- **定义**：簇内所有产品的 `period_change_pct` 的算术平均。
- **判读**：
  - 正数：簇内整体跑赢市场
  - 负数：簇内整体跑输
  - 颜色：正 → `text-success`，负 → `text-danger`

#### 3.3.2 `标准差 σ`（`dispersion.std_change`）

- **定义**：numpy `std(ddof=1)`。
- **判读**：反映簇内成员表现的离散度。σ 大说明簇内产品走势分化严重；σ 小说明行为一致。

#### 3.3.3 `中位数涨跌幅`（`dispersion.median_change`）

- **定义**：numpy `median`。
- **判读**：相比平均数对极端值更稳健。当平均与中位数差异大时，提示存在拉偏的极端产品。

#### 3.3.4 `最大 / 最小`（`dispersion.max_change` / `min_change`）

- **定义**：簇内产品的极值涨跌幅。
- **判读**：最大 - 最小 = 极差（也是后面 3.3.7 的指标）。

#### 3.3.5 `正收益占比`（`dispersion.positive_share`）

- **定义**：`(arr > 0).mean()`，即 `period_change_pct > 0` 的产品占比。
- **判读**：
  - `< 30%` 或 `> 70%`：簇内走势高度同向
  - `40% ~ 60%`：簇内走势分化、对冲

#### 3.3.6 极差（`dispersion.range_pct`）

- **定义**：`max_change − min_change`（百分点）。
- **判读**：单个数字概括簇内"最佳 vs 最差"的差距。

#### 3.3.7 变异系数 CV 与一致性徽章

- **定义**：`cv = std / |mean|`（用绝对值避免符号翻转）。
- **判读**：

  | CV 范围 | 徽章 | 含义 |
  |---|---|---|
  | `< 0.5` | 一致 (bg-success) | 簇内表现高度一致 |
  | `0.5 ~ 1.5` | 分化 (bg-warning) | 表现有差异但仍在同向 |
  | `≥ 1.5` | 高分化 (bg-danger) | 簇内表现严重分化，可能不适合作为单一投资主题 |

### 3.4 Top 5 / Bottom 5 表

每张表的列：

| 列 | 来源 | 含义 |
|---|---|---|
| `#` | `loop.index` | 1-5 名 |
| 代码 / 名称 | `r.product_code` / `r.product_name` | 产品标识 |
| 机构 | `r.institution_code` | 发行机构徽章 |
| 区间涨跌幅 | `r.period_change_pct` | 该产品的涨跌幅，符号着色 |
| 数据区间 | `earliest_nav_date ~ latest_nav_date · span_days 天` | 该产品的 NAV 数据实际跨度（不一定等于 days） |
| 持仓市值 | `r.holding_market_value` | 该产品在最近持仓报告日的持仓市值 |

- **空态**：「无足够数据（产品需要 ≥ 2 条 NAV 记录才能计算涨跌幅）」

### 3.5 综合净值曲线与基准对比

**绘制对象**：单 canvas `chartClusterMarket`，line chart，包含两类 series：

| Series 类型 | 视觉 | 数据 |
|---|---|---|
| 簇综合净值 | 实线 / 加粗 / 颜色 `colors[3]` | `cluster_composite_value_series` 的输出，已重新基准化（起点=100） |
| 市场指数 | 虚线 (`borderDash: [4,3]`) / 颜色 `colors[(i+1) % colors.length]` | `cluster_market_overlay` 选出的指数，按区域自动选择 |

**综合净值的构造**（[queries.py:2015-2146](../src/fundseeker/web/queries.py#L2015-L2146)）：

1. 收集簇内所有产品的逻辑产品键 `(inst, code)`
2. 查出每个键的所有兄弟 `product_id`
3. 窗口 `[end_date − days, end_date]` 内拉取所有 NAV
4. 每个逻辑产品一个 `series[date → value]`（同日期去重）
5. 按日期聚合：`by_date[d] = [每个成员的 NAV]`，等权平均
6. **锚点选择**：取首个 **≥ 80% 成员覆盖** 的日期作为 100；之前的不全日期保留但意义不大
7. 重新基准化：`close = raw / anchor_value * 100`

**期间涨跌口径**：`cluster_run_period_changes` / `cluster_composite_period_change` 以锚点日期（`start_value = 100`）为起点、窗口末日为终点计算 `(end_value / 100 - 1)`，而不是用 `series[0]`。这样与「平均涨跌幅 / 中位数涨跌幅」口径可比，同时避免早期成员覆盖不足带来的抽样偏差。

**判读**：
- 综合净值曲线向上 = 簇内整体净值增长
- 与下方市场指数虚线对比：综合净值斜率 > 指数 → 跑赢市场；反之跑输
- 整体形态特征可反映"该簇策略的弹性"：波动大说明弹性大、波动小说明稳健

**判读常见现象**：
- 综合净值在窗口起点显著高于 100 → 数据稀疏，80% 覆盖的锚点被推迟；属于采集问题
- 综合净值与指数几乎平行 → 簇内持仓与指数高度重合（典型被动型 / 大盘型产品）

### 3.6 持仓分布（`market_breakdown`）

- **含义**：簇内所有持仓按市场区域（`domestic/hk/us/commodity`）累加权重。
- **判读**：决定 `cluster_market_overlay` 选哪些指数对比。例：簇内全部为 A 股，则 overlay 只取 `domestic` bundle（沪深300 + 上证 + 创业板）。

## 4. 几个常见的判读陷阱

1. **报告期 vs 系统日期**：报告期（持仓快照日期）是历史时点，系统日期是查询当下。报告期不更新不代表页面有问题，是上游采集节奏决定。

2. **窗口基准日 vs 系统日期**：图表右端 = `today - 1`，因为市场和产品净值都滞后 1 个交易日。如果你看 7/15 的页面，看到的是 `[6/15, 7/14]` 的窗口。

3. **NAV 数据稀疏**：若产品在窗口内只有 1 条 NAV，则 `period_change_pct = None`，不进入排名；如果整个簇的所有产品都这样，KPI 条和 Top5/Bottom5 都隐藏。

4. **逻辑产品 vs 每日快照**：`product_info` 是每日快照，同一逻辑产品 `(inst, code)` 对应多个 `product_id`。所有 NAV 统计都按逻辑产品键聚合所有兄弟快照的 NAV，而不是仅看当天那一条。

5. **HHI 与 Overlap 数值不可跨簇直接对比绝对大小**：HHI/Overlap 的具体值依赖产品组合本身，只有当簇大小相近、特征维度相同时才有比较意义。要判断"这个簇是不是更集中"，应看它在自己簇内的相对位置。

6. **Silhouette 解读时要分算法**：K-Means 的 silhouette 与 K-Means-asset、K-Means-industry 算法不能直接互相比较，因为特征空间不同。
