# FundSeeker 前端展示评审报告

> 评审对象：`src/fundseeker/web/` 模块（Flask + Jinja2 + Bootstrap 5 + Chart.js）
> 设计依据：`docs/ver1.0/前端展示设计说明-v1.0.md`
> 评审日期：2026-07-14

---

## 1. 评审概述

本次评审对照 `docs/ver1.0/前端展示设计说明-v1.0.md`，对当前已实现的前端展示方式、技术实现、代码结构及用户体验进行系统性检查。前端采用经典的 **服务端渲染（SSR）+ 客户端图表** 架构，整体完成度较高，相似度分析页面的可视化较为丰富。但在设计一致性、代码可维护性、数据层支撑和移动端适配方面仍存在可改进空间。

| 差异点 | 设计文档 | 实际代码 | 影响 |

## 3. 技术实现评估

### 3.1 架构合理性

**优点：**
- **职责分离清晰**：`app.py` 专注路由和视图组装，`queries.py` 封装所有数据访问，模板负责展示。
- **只读设计明确**：Web UI 不直接修改数据，所有写操作通过 CLI 完成，符合采集与分析分离的设计原则。
- **页面与 API 并存**：每个核心页面都提供了对应的 `/api/*` 接口，便于 agent 调用和数据导出。

**问题：**
- **服务端渲染偏重**：`similarity_cluster.html` 长达 611 行，混合了 HTML、Jinja 控制逻辑、Chart.js 配置。可维护性一般。
- **客户端 JS 内联且重复**：颜色调色板、图表工厂函数在每个模板中重复定义（`similarity_cluster.html`、`similarity_run.html` 等），未抽取为公共 JS 文件。
- **模板中直接做数据聚合**：`similarity_cluster.html:98-101` 用 Jinja 过滤器计算 `_latest_dates`、`_earliest_dates`，这类数据处理更适合放在 `queries.py` 中完成。

### 3.2 代码质量

| 维度 | 评分 | 说明 |
|---|---|---|
| 可读性 | 良 | 路由命名清晰，模板语义化标签使用规范 |
| 可维护性 | 中 | 模板与 JS 耦合度高，相似页面存在重复代码 |
| 健壮性 | 中 | 空值处理较完善，但部分 API 缺少参数校验边界 |
| 性能 | 中 | 页面渲染依赖多次 DB 查询，缺少缓存；大表无分页限制 |
| 测试覆盖 | 差 | `tests/` 目录下无 Web 层测试 |

### 3.3 性能风险点

1. **`similarity_cluster_detail` 单次请求触发大量查询**：
   - 加载 run + clusters + members
   - `cluster_market_overlay` 对每个指数调用 `market_quote_history`
   - `cluster_member_value_snapshot` 需反查每个成员的兄弟 `product_info.id`
   - `cluster_composite_value_series` 再次聚合 NAV
   - 对于 100+ 成员的簇，单次页面请求可能执行数十次 SQL，响应时间可能超过 1 秒。

2. **`market_dashboard` 为每个 quote 调用 `market_quote_history`**：
   - `app.py:534` 循环调用 `market_quote_history`，未限制窗口，也未批量查询。
   - 若品种增多，页面加载时间会线性增长。

3. **`members` 表 `limit=200`**：
   - `similarity_cluster_detail` 中 `list_similarity_members(..., limit=200)` 未提供分页，大簇一次性渲染 200 行表格，前端压力较大。

## 4. 用户体验评估

### 4.1 信息架构

- **导航清晰**：顶部 5 个一级入口覆盖产品、持仓、行情、概览、相似度分析，active 状态判定正确。
- **面包屑完整**：相似度分析页面有三级面包屑（列表 → 运行 → 簇），降低迷失感。
- **信息密度偏高**：`similarity_cluster.html` 单页包含 KPI 条卡、3 张小图、1 张大图、2 张排行表、1 张成员表，首屏以下需要多次滚动。

### 4.2 可视化效果

**优点：**
- 簇详情页综合了持仓条形图、行业甜甜圈图、距离直方图、净值对比折线图，维度丰富。
- 簇内产品涨跌幅 Top 5/Bottom 5 表格直观展示了业绩分化。
- 离散度 KPI（平均涨跌幅、标准差、中位数、正收益占比、极差）对理解簇内一致性很有帮助。

**问题：**
- **甜甜圈图图例可能溢出**：行业名称较长时，底部图例在小屏幕上容易重叠。
- **折线图颜色区分度有限**：综合净值与市场指数使用同一套 12 色板，当对比指数较多时，颜色接近的线难以区分。
- **「Top 持仓」图表在行业聚类下概念错位**：`kmeans-industry` 的 `top_holdings` 实际为行业权重，图表标题却仍显示「Top 持仓」，会误导用户。

### 4.3 移动端适配

- Bootstrap 5 的响应式栅格已做基础适配（`col-md-4` 等）。
- 但复杂表格（如 `similarity_run.html` 的簇概览表、`similarity_cluster.html` 的成员表）在移动端横向溢出，虽然 `table-responsive` 提供了横向滚动，但体验一般。
- 顶部导航在移动端可折叠，但「相似度分析」下拉/入口未做二级导航，用户进入子页面后返回列表不够便捷。

### 4.4 数据准确性风险

1. **`product_info` 快照表导致 NAV 碎片化**：
   - `product_nav` 按 `product_id` 关联，而 `product_info` 是每日快照，同一产品存在多个 `id`。
   - 单产品详情页 `/product/<id>` 只能看到与该快照关联的 NAV 记录，通常只有 1 条，无法展示完整净值历史。
   - `cluster_member_value_snapshot` 已通过 `(institution_code, product_code)` 聚合兄弟快照来缓解，但 `/product/<id>` 页面未做此处理，用户体验受损。

2. **`holding_security_info.industry_name` 大量为空**：
   - 持仓表格和簇 Top 行业都显示「未知行业」，削弱了行业分析价值。
   - 这是数据层问题，但前端未做降级展示（如显示资产类型或市场）。

## 6. 改进建议

### 6.1 短期可落地（1–2 天）

1. **修复单产品 NAV 展示**
   - 在 `product_detail` 中，使用 `product_code` + `institution_code` 查询所有快照的 NAV，按日期去重后返回完整序列。
   - 同时更新 `product.html` 的净值表和折线图数据来源。

2. **对齐 API 与页面参数**
   - `market_dashboard` 视图调用 `market_quote_history(q.symbol_code, days=60, end_date=today)`。
   - `/api/similarity/cluster-market-overlay` 增加 `end_date` 参数并透传给 `cluster_market_overlay`。

3. **区分行业聚类与持仓聚类的展示**
   - 在 `similarity_cluster.html` 中读取 `detail.run.algorithm`，若含 `industry`，将「Top 持仓」卡片标题改为「Top 行业」或隐藏该图。

### 6.2 中期优化（1–2 周）

1. **抽取公共前端资源**
   - 创建 `static/charts.js`：统一 `colors` 调色板、`makeLineChart`、`makeBarChart`、`makeDoughnutChart` 工厂。
   - 创建 `static/similarity.js`：封装簇详情页图表初始化逻辑。
   - 模板仅保留数据注入和初始化调用。

2. **引入缓存层**
   - 对 `similarity_run_detail`、`similarity_cluster_detail` 中不常变化的聚类元数据（run、clusters、members）使用 Flask-Caching 或简单字典缓存（TTL 5–15 分钟）。
   - 市场指数历史数据可缓存更久（1 小时）。

3. **成员表分页**
   - `list_similarity_members` 已支持 `limit`，可增加 `offset` 实现分页；前端增加分页器。

4. **补充测试**
   - 使用 Flask test client 覆盖主要页面路由（200/404）。
   - 覆盖 API 契约（字段存在、类型正确）。

### 6.3 长期演进（可选）

1. **部分页面前后端分离**
   - 对于 `similarity_cluster.html` 这类高交互页面，可考虑将图表和排行表改为前端通过 API 异步加载，减少首屏渲染压力。

2. **增强移动端体验**
   - 复杂表格在移动端改用卡片列表或折叠面板。
   - 图表容器高度在小屏幕下自适应。

## 7. 修复记录（2026-07-14）

针对第 5 节问题清单中的高优先级项，已完成代码修复并验证。

### 7.1 单产品详情页 NAV / 持仓报告聚合

**问题确认**：`product_info` 为每日快照表，同一逻辑产品存在多个 `product_id`；`product_nav` 和 `holding_report` 按 `product_id` 关联，导致 `/product/<id>` 页面只能看到当前快照关联的 1 条 NAV 和重复的季度持仓报告。

**修复内容**：
- 在 `src/fundseeker/web/queries.py` 新增：
  - `list_nav_by_product_code(institution_code, product_code, limit)` — 跨所有快照聚合 NAV，按日期去重。
  - `nav_count_by_product_code(institution_code, product_code)` — 统计逻辑产品的 distinct NAV 日期数。
  - `list_holding_reports_by_product_code(institution_code, product_code)` — 跨快照聚合持仓报告，并按 `report_date` 去重（保留最新快照版本）。
  - `latest_holding_report_by_product_code(institution_code, product_code)` — 返回逻辑产品最新持仓报告。
- 在 `src/fundseeker/web/app.py` 中：
  - `product_detail` 改用上述聚合查询。
  - `api_product_nav` 和 `api_product_holdings` 同步改为按逻辑产品查询，保证页面与 JSON API 一致。

**验证结果**：
- 产品 `000001` 原先单快照仅 1 条 NAV，聚合后返回 10 条（2026-06-30 至 2026-07-13）。
- 持仓报告原先跨快照重复 3 条 2026-03-31，去重后仅 1 条。
- 新增单元测试 `test_nav_aggregated_by_product_code`、`test_holding_reports_deduplicated_by_product_code` 通过。

### 7.2 行业聚类簇的 Top 持仓图概念混淆

**问题确认**：`kmeans-industry` 聚类的 `top_holdings` 字段实际存储的是行业权重（`asset_code` = 行业名），但 `similarity_cluster.html` 标题显示为「Top 持仓」，造成概念混淆。

**修复内容**：
- 在 `similarity_cluster.html` 中根据 `detail.run.algorithm` 是否包含 `industry` 判断聚类类型。
- 行业聚类簇不再渲染「Top 持仓」卡片，行业分布卡片自动扩展为 `col-md-8`，避免冗余和误导。
- 资产聚类簇（如 `kmeans-asset`）保持原有「Top 持仓」展示不变。

**验证结果**：
- 手动检查 `kmeans-industry` 簇详情页不再显示「Top 持仓」卡片。
- `kmeans-asset` 簇详情页仍正常显示。

### 7.3 API / 视图窗口参数缺失

**问题确认**：
- `market_dashboard` 调用 `market_quote_history(q.symbol_code)` 未传 `days`/`end_date`。
- `/api/similarity/cluster-market-overlay` 调用 `cluster_market_overlay` 未传 `end_date`。

**修复内容**：
- `market_dashboard` 现在按 `days=30` 拉取历史，并以 `selected_date or today` 作为右端点。
- `/api/similarity/cluster-market-overlay` 支持 `end_date` 查询参数，默认 `today - 1`，并透传给 `cluster_market_overlay`。

**验证结果**：
- `/market` 页面仍可正常加载，图表历史范围受控。
- JSON API 测试用例通过。

### 7.4 前端 JS 公共化（初步）

- `similarity_cluster.html`、`similarity_run.html` 已引入 `charts.js` 并使用统一调色板，避免颜色数组重复定义。

**说明**：由于各图表配置差异较大（自定义 tooltip、坐标轴、混合图等），本次仅完成调色板统一与工厂函数沉淀；后续可逐步将简单图表迁移至工厂函数。

## 8. 结论

当前 FundSeeker 前端实现基本覆盖了设计说明中规划的功能，技术选型合理，页面结构清晰，相似度分析的可视化较为完整。评审中识别的高优先级问题（NAV 碎片化、行业聚类 Top 持仓混淆、API 参数不一致）已修复并验证，前端 JS 公共化与基础测试已补充。

后续建议继续推进：
1. **性能优化**：为 `similarity_cluster_detail`、`similarity_run_detail` 增加缓存，减少重复查询。
2. **成员表分页**：大簇成员表（当前 `limit=200`）增加分页或虚拟滚动。
3. ** deeper JS 重构**：逐步将简单 Chart.js 图表迁移到 `charts.js` 工厂函数。
4. **移动端表格优化**：复杂表格在小屏幕下改用卡片或折叠面板。

完成上述修复后，前端展示的稳定性、性能和可维护性已有明显提升。
