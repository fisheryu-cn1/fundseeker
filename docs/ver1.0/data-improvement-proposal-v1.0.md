### 1.2 关键数据缺陷

1. **历史净值缺失严重**：当前每个产品平均只有 **1 条**净值记录，仅覆盖最新/采集日净值，无法进行时序分析、回撤计算、波动率分析等。
2. **部分产品无净值**：SPD 有 2,159 个产品、BOC 有 63 个产品、各基金子公司也有少量产品未获取到净值。
3. **净值异常值需甄别**：部分产品净值为 `1.00`，需区分是现金管理类产品的正常估值，还是数据源默认值。
4. **无持仓数据**：当前未采集任何产品的底层持仓（股票、债券、行业配置、大类资产），无法分析产品风险暴露和收益来源。

## 2. 净值数据质量专项分析

### 2.1 净值为 1.00 的分布

| 机构 | 1.00 净值记录数 | 主要类型 | 分析 |
|------|-----------------|----------|------|
| CITIC | 1,131 | money_market: 749, other: 382 | 现金管理类（日盈象/天天利系列）占 66%，净值稳定在 1.00 属于正常；其余 `other` 类型需人工复核 |
| SPD | 1,014 | other: 605, money_market: 409 | 现金管理类 409 条合理；605 条 `other` 类型存在默认值嫌疑 |
| JX | 258 | fixed_income: 257, mixed: 1 | 固收类产品若采用摊余成本法，净值 1.00 可能合理，但需结合产品说明书确认 |
| GF/ChinaAMC | 各 1 条 | qdii / mixed | 样本过少，暂无法判断 |

### 2.2 可疑净值识别规则

建议通过以下规则标记需要复核的净值：

1. **非现金管理类产品**净值等于 1.00 且成立日期早于 6 个月前。
2. **成立多年**的产品净值长期等于 1.00（波动率为 0）。
3. 净值数据**唯一来源**为官网列表页，且该页面在无数据时常返回 1.00 作为占位。
4. 净值日期与采集日期间隔过长（如超过 7 个工作日）。

按当前数据排查：
- CITIC：成立早于 2024-01-01 但净值仍为 1.00 的产品有 **183 个**，其中多为现金管理型，可接受；非现金管理型需复核。
- JX：成立早于 2024-01-01 但净值仍为 1.00 的产品有 **20 个**。

### 2.3 缺失净值原因分析

| 原因 | 影响机构 | 说明 |
|------|----------|------|
| 接口未返回净值字段 | SPD 部分产品 | 产品列表和净值接口未完全关联 |
| 产品状态为募集/待售 | BOC 等 | 未成立产品无净值 |
| 基金数据解析问题 | YFD/HTF | 早期采集时部分字段缺失 |
| 数据源本身仅提供最新净值 | 全部 | 当前设计未抓取历史净值 |

## 3. 净值数据补充来源研究

### 3.1 公募基金净值（广发、华夏、易方达、汇添富）

| 数据源 | 覆盖内容 | 稳定性 | 建议优先级 |
|--------|----------|--------|------------|
| **天天基金网历史净值 API** | 全部历史净值（按基金代码） | 高 | ⭐⭐⭐ 首选 |
| `fund.eastmoney.com/Data/Fund_JJJZ_Data.aspx` | 最新净值 + 日涨跌幅 | 高 | 已使用 |
| **基金公司官网** | 完整历史净值、分红记录 | 中高 | 备选 |
| **AKShare `fund_*_fund_info_em`** | 理财型/ETF/货币/分级基金历史净值 | 高 | 推荐接入 |

**天天基金历史净值接口示例**：

```text
https://fundf10.eastmoney.com/F10DataApi.aspx?type=lsjz&code=000001&page=1&per=20
```

返回 HTML 表格，包含：净值日期、单位净值、累计净值、日增长率、申赎状态、分红送配。

### 3.2 银行理财产品净值

| 数据源 | 覆盖内容 | 稳定性 | 建议优先级 |
|--------|----------|--------|------------|
| **各理财子公司官网** | 最新净值、部分历史净值 | 中 | 已部分使用 |
| **中国理财网** | 全市场银行理财净值、公告 | 高（需过验证码） | ⭐⭐⭐ 权威但技术门槛高 |
| **代销银行渠道**（招行、工行、建行 APP/官网） | 部分产品净值 | 中低 | 针对特定产品补充 |
| **上海清算所/中债登** | 债券估值，可间接校验固收类净值 | 高 | 校验用 |

**中国理财网优势**：作为全国银行业理财信息登记系统的官方查询平台，理论上覆盖全部银行理财产品的净值、公告和定期报告。但当前存在：
- 文字点选验证码
- 核心搜索接口 `/lcw-fe-service/prod/search` 使用 RSA+AES+HMAC 加密

**建议处理方案**：
1. 短期：继续从各理财子公司官网获取最新净值。
2. 中期：研究中国理财网加密流程，在受控环境中通过浏览器自动化完成验证码后复用前端 JS 加密逻辑调用 API。
3. 长期：如业务需要全量权威数据，考虑申请银行业理财登记托管中心的数据服务或购买 Wind/Choice 等专业金融终端。

## 4. 持仓数据获取渠道研究

### 4.1 公募基金持仓

公募基金持仓披露完整、渠道成熟，是优先补充对象。

| 数据源 | 覆盖内容 | 频率 | 建议优先级 |
|--------|----------|------|------------|
| **天天基金 F10 持仓 API** | 前十大重仓股、占净值比、持股数、市值 | 季度 | ⭐⭐⭐ 首选 |
| **天天基金行业配置 API** | 行业配置占比 | 季度 | ⭐⭐⭐ 首选 |
| **天天基金债券持仓 API** | 前五大/前十大债券持仓 | 季度 | ⭐⭐⭐ 首选 |
| **巨潮资讯网（CNINFO）** | 基金季报/半年报/年报全文 | 季度/半年/年度 | ⭐⭐⭐ 完整披露 |
| **AKShare `fund_portfolio_hold_em`** | 前十大重仓股 | 季度 | 推荐接入 |
| **雪球基金** | 大类资产配置比例（股票/债券/现金） | 季度 | 备选 |

**天天基金持仓 API 示例**：

```text
https://fundf10.eastmoney.com/FundArchivesDatas.aspx?type=jjcc&code=000001&topline=10&year=2024&month=12
```

返回 HTML 表格，包含：序号、股票代码、股票名称、占净值比例、持股数（万股）、持仓市值（万元）、季度。

### 4.2 银行理财产品持仓

银行理财产品的持仓披露不如公募基金规范，但可通过以下渠道获取：

| 数据源 | 覆盖内容 | 频率 | 建议优先级 |
|--------|----------|------|------------|
| **中国理财网产品公告/投资报告** | 部分产品季度投资报告、前十大持仓 | 季度 | ⭐⭐⭐ 权威但门槛高 |
| **各理财子公司官网信息披露** | 产品说明书、季度/年度报告 | 季度/年度 | ⭐⭐ 已部分获取 |
| **产品托管报告** | 资产组合、大类资产配置 | 季度 | ⭐⭐ 需解析 PDF |
| **代销银行 APP** | 部分产品展示持仓大类 | 不定期 | ⭐ 补充用 |

**建议**：银行理财持仓以**大类资产配置**（固定收益类、权益类、现金及银行存款、衍生品类等）和**前十大资产**为目标字段，不追求股票级明细。

### 4.3 股票/权益类产品的主要持仓

对于权益类、混合类产品，建议按以下层次获取持仓：

1. **公募基金**：直接获取前十大重仓股（股票代码、名称、占比、市值）。
2. **银行理财子权益/混合产品**：获取季度投资报告中的前十大资产（可能包含股票、债券、资管计划等）。
3. **ETF/指数基金**：通过交易所披露获取完整持仓（通常每日或每季度）。
4. **QDII 产品**：通过季报获取海外资产类别和地区分布。

## 5. 数据模型扩展建议

为支持净值历史时序和持仓数据，建议在现有模型基础上扩展：

### 5.1 新增字段/表

1. **`product_info` 扩展字段**（可选）
   - `valuation_method`: 估值方法（市值法/摊余成本法/混合）
   - `disclosure_frequency`: 披露频率
   - `asset_management_report_url`: 投资报告链接

2. **新增 `product_holding` 表**
   - 记录产品持仓明细（股票/债券/基金/其他资产）
   - 字段：`product_id`, `report_date`, `asset_code`, `asset_name`, `asset_type`, `weight`, `market_value`, `share_quantity`, `data_source`, `created_at`

3. **新增 `product_asset_allocation` 表**
   - 记录大类资产配置比例
   - 字段：`product_id`, `report_date`, `asset_class`, `weight`, `market_value`, `data_source`

4. **新增 `product_dividend` 表**（可选）
   - 记录分红、拆分事件，用于累计净值复权

## 6. 改进路线图建议

### 第一阶段：补齐公募基金历史净值与持仓（1-2 周）

**目标**：优先提升公募基金（GF、ChinaAMC、YFD、HTF）的数据质量。

**任务**：
1. 接入天天基金历史净值 API，为每只基金补充近 1-3 年历史净值。
2. 接入天天基金持仓 API，为权益/混合/债券基金补充最新季度前十大持仓。
3. 接入天天基金行业配置和债券持仓 API，丰富持仓维度。
4. 建立净值异常值检测任务，标记净值缺失、长期 1.00、净值日期过期等异常。

**预期收益**：
- 公募基金历史净值覆盖率从 1 条/产品提升至数百条/产品。
- 权益/混合类产品获得股票级持仓数据，可计算行业暴露、集中度等。

### 第二阶段：银行理财历史净值补充（2-3 周）

**目标**：提升银行理财子（SPD、CITIC、BOC、JX、ZY、CEB）的历史净值覆盖。

**任务**：
1. 分析各理财子公司官网是否提供历史净值查询接口（如产品详情页）。
2. 对 SPD、CITIC、BOC 等已实现采集器，扩展历史净值抓取逻辑。
3. 评估中国理财网验证码/加密方案，在受控环境（如带人工复核的 Playwright 流程）下尝试获取全量数据。
4. 建立跨数据源校验机制：将中国理财网/代销渠道数据与官网数据进行比对。

**预期收益**：
- 银行理财产品历史净值覆盖率提升。
- 形成多源校验能力，识别异常净值。

### 第三阶段：银行理财持仓与报告采集（3-4 周）

**目标**：获取银行理财产品的持仓大类和前十大资产。

**任务**：
1. 采集各理财子公司官网的产品说明书、季度/年度报告 PDF。
2. 解析 PDF/网页中的投资组合信息、大类资产配置、前十大资产。
3. 对中国理财网披露的投资报告进行结构化抽取。
4. 建立持仓数据与产品类型的关联分析。

**预期收益**：
- 银行理财产品获得资产配置和主要持仓数据。
- 支持产品风险画像和收益归因分析。

### 第四阶段：数据质量监控体系（持续）

**目标**：建立自动化的数据质量监控和告警。

**任务**：
1. 每日/每周统计各机构产品数、净值覆盖率、持仓覆盖率。
2. 自动标记异常净值（如非货基长期 1.00、净值日期滞后、净值跳变过大等）。
3. 建立数据源可用性监控，当某个机构接口失败时自动切换备用源或告警。
4. 定期生成数据质量报告。

## 7. 技术实现建议

### 7.1 使用 AKShare 作为补充工具

AKShare 封装了天天基金、东方财富、巨潮资讯等多个数据源，可大幅减少接口开发成本。建议：

```bash
pip install akshare
```

优先使用接口：
- `ak.fund_open_fund_info_em(fund="000001", indicator="单位净值走势")` —— 历史净值
- `ak.fund_portfolio_hold_em(symbol="000001", date="2024")` —— 股票持仓
- `ak.fund_portfolio_industry_allocation_em(symbol="000001", date="2024")` —— 行业配置
- `ak.fund_portfolio_bond_hold_em(symbol="000001", date="2024")` —— 债券持仓

### 7.2 浏览器自动化策略

对于中国理财网等高防护站点，建议：
1. 使用 Playwright 打开页面。
2. 检测验证码类型（文字点选/滑动）。
3. 文字点选验证码可通过截图 + OCR/视觉模型识别文字位置后点击。
4. 完成验证后，通过页面 JS 调用 Vue/Pinia store 中的加密方法，复用前端加密逻辑请求 API。
5. 将获取的加密响应在浏览器端解密后返回给 Python。

### 7.3 PDF 解析

对于理财子公司投资报告 PDF，建议：
1. 使用 `pypdf` / `pdfplumber` / `PyMuPDF` 提取文本和表格。
2. 使用正则或 LLM 提取关键字段：大类资产配置比例、前十大资产、风险提示等。
3. 建立人工复核流程，确保关键字段抽取准确率。

## 8. 风险与注意事项

1. **合规风险**：中国理财网等数据源有反爬机制，大规模抓取需控制频率，避免对源站造成压力。建议遵守 robots.txt，必要时申请官方数据接口。
2. **数据准确性**：不同数据源可能存在差异，需建立主数据源和校验机制。
3. **验证码成本**：中国理财网验证码需要 OCR 或人工介入，自动化程度有限。
4. **持仓披露滞后**：基金持仓按季度披露，存在 15-45 天滞后；银行理财持仓披露更不固定。
5. **估值方法差异**：现金管理类产品采用摊余成本法，净值稳定在 1.00 是正常的，不能简单视为异常。

## 9. 下一步行动建议

鉴于你要求"先不改动代码"，建议下一步按以下顺序推进：

1. **确认优先级**：优先公募基金还是银行理财子？
2. **试点 AKShare**：先用 AKShare 抓取 1-2 只基金的历史净值和持仓，验证数据质量。
3. **验证中国理财网方案**：评估是否投入资源解决验证码/加密问题。
4. **细化数据模型**：确认是否需要新增 `product_holding`、`product_asset_allocation` 等表。
5. **制定排期**：根据业务需求，确定第一阶段的实现范围和截止时间。
