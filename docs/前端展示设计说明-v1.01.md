## 2. 市场行情页面性能修复（28s → <1s）

### 2.1 问题描述

`/market`（`market_dashboard`，`web/app.py:541`）冷启动耗时长：

- **基线（修复前）**：~28 秒
- **目标**：<1 秒

根因有两条，互相叠加：

1. `list_market_quotes` 不带 `asset_class` 过滤，把全部 1864 个 `stock` 行也一并拉出来再渲染（虽然模板不显示，但模板渲染逻辑先遍历 `quotes`）。
2. 路由再对每条记录单独调用 `market_quote_history(symbol_code, days=30, end_date=...)`，形成 N+1：1864 × 1 次 round-trip × 15ms ≈ 28s。

### 2.2 修复策略（三件套）

| 修复 | 文件:行 | 做法 |
|---|---|---|
| ① 默认 `asset_class` 过滤 | `web/queries.py:1096` | `list_market_quotes` 新增 `asset_classes` 参数，默认 `_DEFAULT_MARKET_ASSET_CLASSES = ("index", "commodity")`；传 `()` 可关闭 |
| ② N+1 → 单次批量查询 | `web/queries.py:1175` | 新增 `market_quote_history_batch(symbol_codes, days, end_date)`；`web/app.py:541` 调用一次拿到所有 30 天序列 |
| ③ 复合索引 | `models/tables.py:351`、`scripts/migrate_market_quote_index.py` | 新增 `ix_market_quote_asset_class_date_symbol ON market_quote (asset_class, quote_date, symbol_code)` |

### 2.3 行为约定

- **默认值**：`list_market_quotes()` 不传 `asset_classes` 时，仅返回 `asset_class ∈ ('index', 'commodity')` 的行。这是「市场行情仪表盘」语义的最小集合。
- **股票行情查询**：如需查询 `asset_class = 'stock'`（如个股补录后的行情回放），需显式传 `asset_classes=()`，避免与默认过滤冲突。
- **CLI 同步**：`scripts/fundseeker_query.py` 的 `market` 子命令也走 `list_market_quotes`，自动继承默认过滤；该命令的语义同样为「宏观行情」，不需要支持股票行情。
- **API 接口**：`/api/market/quotes`（`web/app.py:802`）同样继承默认过滤；前端如需展示个股行情，应新增独立 endpoint，避免污染宏观行情 API 的语义。

### 2.4 数据库迁移

```bash
PYTHONPATH=src .venv/bin/python scripts/migrate_market_quote_index.py
```

幂等：`CREATE INDEX IF NOT EXISTS`。已存在的同名索引不会重建；新部署依赖 `models/tables.py:351` 的 `Index(...)` 声明自动建出。

### 2.5 验证

| 检查项 | 命令 / 行为 | 期望 |
|---|---|---|
| 路由耗时 | 浏览器访问 `http://127.0.0.1:5001/market`，看 Network | < 1s |
| 行数 | `list_market_quotes()` 不传参 | 仅返回 `asset_class IN ('index', 'commodity')` 的行（约 14 个品种） |
| 索引存在 | `\\d market_quote`（psql） | 包含 `ix_market_quote_asset_class_date_symbol` |
| EXPLAIN | 对 `WHERE asset_class IN (...) AND symbol_code IN (...) AND quote_date <= ...` 跑 EXPLAIN | 使用复合索引（Index Scan） |

## 4. 后续可选项（不在本次范围）

- 把 `asset_classes` 做成 UI 控件（模板顶部加按钮组），允许用户在「宏观行情」和「全量」之间切换。
- 引入短期缓存（5 分钟内同一日期不重查）以降低页面冷启动次数；当前规模不构成瓶颈。
- `market_quote_history_batch` 当前用 Python 端 trim 到 `days` 条，更大规模时可改为 PostgreSQL `DISTINCT ON (symbol_code)` + `LIMIT` 的窗口查询。
