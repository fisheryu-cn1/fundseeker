## 1. 修复范围与依据

本次修复来自一次对采集链路（`runner.py` + `http.py` 及调用链）的多轮评审实验：同一模型在同一代码基线上独立评审多次（带结构化评审指引与不带各若干轮），共产出 7 份报告；随后对全部 85 条意见逐条以基线代码快照复核，确认 35 个真实问题主题。本次先修复其中两项已确认、影响明确且改动可控的缺陷：

| # | 级别 | 缺陷 | 复核确认情况 |
|---|---|---|---|
| 1 | P2 | 重试循环内每次重试都重复执行节流延迟 `_enforce_delay`，与指数退避叠加，失败请求等待时间被放大 | 多轮独立评审均报出（3/3 轮命中） |
| 2 | P2 | `--holding-years` / `--years` 数值参数无硬上限，传入大值可致单产品数万次 HTTP 请求 | 仅带评审指引的轮次报出（该类别属规则强制遍历的检查面） |

## 2. 修复执行情况逐项说明

### ✅ 修复 #1（P2）：重试不再叠加礼貌延迟

**位置**：`src/fundseeker/utils/http.py`（`_request_with_retries`）

**修复内容**：节流延迟仅在第 1 次尝试（`attempt == 0`）前执行；重试路径只支付指数退避，不再叠加 `_enforce_delay`。

```python
for attempt in range(self.max_retries + 1):
    # Polite delay only before the first attempt: retries already pay
    # exponential backoff below, so delaying here too would double the
    # wait on every failed request (P2, review 2026-08-20 fs 分析 §2.1).
    if attempt == 0:
        self._enforce_delay()
    try:
        ...
```

**语义保持**：跨调用的最小间隔语义不变——`_enforce_delay` 内部对 `_last_request_time` 的更新在首次尝试前照常触发。

### ✅ 修复 #2（P2）：年数参数硬上限

**位置**：`scripts/fundseeker_cli.py`（collect 子命令 `--holding-years`）与 `scripts/run_holding_collection.py`（`--years`）

**修复内容**：两个入口在参数消费点统一钳制到 `1..10`，并更新帮助文本。

```python
# fundseeker_cli.py（main 内，args 解析后）
if getattr(args, "holding_years", None) is not None:
    args.holding_years = max(1, min(int(args.holding_years), 10))

# run_holding_collection.py（调用点）
years=max(1, min(int(args.years), 10)),  # clamp (review 2026-08-20)
```

**边界行为**（独立复审逐项核验）：

| 输入 | 行为 |
|---|---|
| 默认 1 / 恰好 10 | 不变 |
| 11 / 1000 | 收敛为 10 |
| -5 | 收敛为 1 |
| 0 | 收敛为 1（见 §3 回归修正） |
