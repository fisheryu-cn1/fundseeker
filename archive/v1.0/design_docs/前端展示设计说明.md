## 2. 全局设计

### 2.1 `base.html` 布局

固定结构：

```
<body>
  <nav class="navbar navbar-dark bg-dark">…5 个一级入口…</nav>
  <main class="container-fluid pb-5">{% block content %}{% endblock %}</main>
  <footer>…</footer>

```

5 个一级入口及 active 判定：

| 入口 | URL endpoint | active 条件 |
|---|---|---|
| 产品检索 | `search` | `request.endpoint == 'search'` |
| 持仓检索 | `holdings_browse` | `request.endpoint == 'holdings_browse'` |
| 数据概览 | `dashboard` | `request.endpoint == 'dashboard'` |
| 市场行情 | `market_dashboard` | `request.endpoint == 'market_dashboard'` |
| 相似度分析 | `similarity_index` 等 5 个 | `request.endpoint in ('similarity_index','similarity_run_detail','similarity_cluster_detail','similarity_product_view','similarity_compare')` |

### 2.2 自定义 CSS（`static/style.css`）

只在 Bootstrap 之上做轻量覆盖：

- `body`：背景 `#f5f7fa`，中文字体栈（`-apple-system`, `PingFang SC`, `Microsoft YaHei` …）
- `.card`：边框 `rgba(0,0,0,0.08)`（更柔和）
- `table thead th`：加粗、不换行
- `.badge`：字重 500
- `code`：粉红底 `#f9f2f4`
- `.chart-card { min-height: 380px; }`：统一图表卡最小高度
- `.text-truncate`、`.chart-card canvas { max-width: 100%; }`

### 2.3 Jinja 过滤器（`register_filters`，app.py:49）

| 过滤器 | 输入 | 输出 | 用途 |
|---|---|---|---|
| `fmt_money` | 数字 / None | `1.2345` 或 `—` | 净值、金额（保留 4 位小数） |
| `fmt_pct` | 0~1 的小数 / None | `12.34%` | 收益率、占比 |
| `fmt_date` | `date` / `datetime` | `YYYY-MM-DD` | 日期 |
| `fmt_dt` | `datetime` | `YYYY-MM-DD HH:MM:SS` | 时间戳 |
| `holding_market` | 市场码 `SH/SZ/...` | `上海/深圳/...` | 持仓表 |
| `asset_class` | 资产类型码 | `股票/债券/...` | 持仓表 |
| `market_region` | `domestic/us/hk/...` | `A股/美股/...` | 行情卡片 |
| `fmt_volume(volume, unit)` | 整数 + `lot/share/contract` | `1.23亿手` 等 | 行情表 |
| `fmt_amount` | 数字 / None | `1.23亿` 等 | 金额 |

### 2.4 通用约定

- **没有 JSON 渲染**：所有页面都是 `render_template(...)` 服务端渲染；JSON 仅通过 `/api/*` 接口暴露。
- **分页**：所有列表页（`search`、`holdings_browse`）默认 `page_size=25`，分页器固定渲染前 1 页 / 后 1 页 + 当前页 ± 2 + 省略号。
- **颜色语义**：正收益 `text-success`、负收益 `text-danger`、中性 `text-muted`。
- **空数据**：每个区块都有 `<div class="text-muted text-center py-…">无数据</div>` 或表格 fallback `<tr><td colspan=N>…</td></tr>`。
- **测试**：Web 层基础测试位于 `tests/test_web.py`，使用 Flask test client 覆盖主要页面路由、API 契约及跨快照聚合行为。

## 4. 各页面详细设计

### 4.1 `search.html` — 产品检索首页

**布局**：

```
[col-md-3 aside]  筛选表单          | [col-md-9 section]  结果列表 + 分页
```

**侧栏表单**（GET）字段：

| name | 来源 | 取值 |
|---|---|---|
| `q` | 文本 | 关键字（代码或名称模糊匹配） |
| `institution` | 下拉 | `queries.distinct_institutions()` |
| `type` | 下拉 | `queries.PRODUCT_TYPES` 常量 |
| `risk` | 下拉 | `queries.RISK_LEVELS = ['L1'..'L5']` |
| `status` | 下拉 | `queries.distinct_statuses()` |

**结果表**列：代码 / 名称 / 机构 / 类型 / 风险 / 最新净值 / 净值日期 / 操作（详情链接）。

**数据查询**：`queries.list_products(...)`，`page_size=25`，`page` 从 URL `?page=N` 解析，最小为 1。

**空态**：「没有匹配的产品」+ 提示使用表单查询。

### 4.2 `product.html` — 产品详情

**路由解析**：`/product/<int:product_id>`，404 if `get_product is None`。

**布局**（自上而下）：

```
面包屑（产品检索 → 机构 → 代码）
产品标题 + 状态徽章 + 「查看相似度归属」按钮
基本信息卡（10 个字段 dl.row）
净值历史卡 + 折线图（chart.js）
持仓信息卡（报告期切换 tabs + 6 项汇总指标 + 资产配置 doughnut + 持仓明细表）
收益率卡
费率卡
该机构最近采集记录表
```

**关键字段**：

- `chart_labels` / `chart_values`：净值历史前 50 条，按日期升序。**实际实现中按 `(institution_code, product_code)` 聚合所有快照的 `product_nav`，而非仅当前 `product_id`**。
- `holding_reports`：所有报告期，pill-tabs 选择。**按逻辑产品聚合，并对同一 `report_date` 去重**。
- `selected_report`：当前选中报告（`?report_id=` 不存在时取最新）
- `security_info_map`：`(asset_code, market) → HoldingSecurityInfo`，避免逐行查
- `holding_summary`：`ProductHoldingSummary` 行（top10_weight 等）

**Chart.js**：

| Canvas | 类型 | 数据 |
|---|---|---|
| `navChart` | `line` | `chart_labels` × `chart_values`，蓝色填充 |
| `allocationChart` | `doughnut` | `asset_allocations` 的 asset_class / weight |

### 4.3 `holdings.html` — 持仓检索

**布局**：与 `search.html` 一致，左侧筛选 + 右侧结果。

**侧栏表单字段**：

| name | 来源 |

### 4.4 `market.html` — 市场行情仪表盘

**路由解析**：`/market`，`?date=YYYY-MM-DD` 可选。

**布局**：

```
标题 + JSON API 按钮 + 「各品种最新数据」徽章（仅当未选日期）
交易日选择器（最新 + 最近 30 个交易日）

```

**区域顺序**：`region_order = ['domestic', 'us', 'hk', 'commodity']`（模板内联常量）。

**卡片字段**（每只品种一个卡片）：名称 + 区域徽章 / 收盘价 / 涨跌幅（红涨绿跌）/ 涨跌额 / 开/高/低/昨收。

**图表**（条件渲染）：

| Canvas | 区域筛选 | 数据 |
|---|---|---|
| `chartDomestic` | `region == 'domestic'` | `chart_datasets` 中 A 股 |
| `chartGlobal` | `region in ['us', 'hk']` | 美股 + 港股 |

两个图都用 `makeChart(canvasId, datasets)` 工厂函数：

- x 轴：所有日期的并集并排序

**明细表**列：品种 / 区域 / 开盘 / 最高 / 最低 / 收盘 / 昨收 / 涨跌额 / 涨跌幅 / 成交量（`fmt_volume`）/ 成交额（`fmt_amount`）。

### 4.6 `similarity_index.html` — 聚类运行列表

**路由**：`/similarity`，支持 `?algorithm=` 和 `?date=YYYY-MM-DD` 过滤。

**布局**：

```
报告期筛选按钮组（全部 + 最近 12 个报告期）

4 张 KPI（运行数 / 算法数 / 报告期数 / 最新报告期）
```

### 4.7 `similarity_run.html` — 单次聚类运行详情

**路由**：`/similarity/<int:cluster_run_id>`，404 if run 不存在。

**布局**：

```
面包屑（相似度分析 → 运行摘要）
标题 + JSON API 按钮
KPI 卡条（k / 参与产品数 / 特征维度 / Silhouette / Inertia）
元信息（算法 / 产品类型过滤 / 报告期 / 创建时间）
两张图表（簇规模柱状图 + 跨运行 Inertia 气泡图）
簇概览表（每簇：标签 / 规模 / 期间涨跌 / Top 行业 / Top 持仓 / HHI / Overlap / AC 份额合并占比）
簇 × 行业矩阵表（仅当 industry_rows 非空）
```

**图表**：

| Canvas | 类型 | 说明 |
|---|---|---|
| `chartClusterSizes` | `bar` | x = 簇标签（派生或 `簇 #N`），y = size |
| `chartInertia` | `bubble` | 全部已保存运行，按算法分数据集 |

**簇标签**：聚类 service 在生成 `ClusterProfile` 时已根据 `top_industries` 调用 `derive_cluster_label()` 计算并持久化到 `similarity_cluster.cluster_label`。路由层优先使用持久化的 `cluster.cluster_label`，缺失时才回退到路由层重新派生；最终兜底为 `簇 #N`。标签形式如「通信设备 + 半导体 + 元件」「白酒 + 白色家电 + 摩托车及其他」，见 §7.1。

**期间涨跌列**：路由层调用 `queries.cluster_run_period_changes(cluster_run_id, days=60, end_date=today-1)`，对每个簇基于等权合成净值计算区间涨跌幅。合成净值以窗口内首个 **≥ 80% 成员覆盖** 的日期为锚点归一化为 100，期末值相对锚点计算 `(期末值 / 100 - 1)`，避免早期成员覆盖不足导致的抽样偏差。结果按 `cluster_id` 注入模板；正收益显示为 `text-success`，负收益显示为 `text-danger`，无数据时显示 `—`。统计口径与单簇详情页的「综合净值」保持一致。

### 4.8 `similarity_cluster.html` — 单簇详情（核心页面）

**路由**：`/similarity/<int:cluster_run_id>/cluster/<int:cluster_id>`，参数 `?days=`、`?sort=`。

**核心参数计算**（路由层）：

```
days       = int(request.args.get('days', default=60), 10..180)
sort       = request.args.get('sort', default='distance')
end_date   = date.today() - timedelta(days=1)   # 1 天市场滞后
window_start = end_date - timedelta(days=days)
query_date = date.today()
```

**数据查询**：

| 数据 | 查询函数 |
|---|---|
| 簇视图 `cluster` | `queries.get_similarity_run_by_id(id)` + 派生标签 |
| 成员列表 `members` | `list_similarity_members(sort=sort, limit=200)` |
| 行情图表 `market_chart_data` | `cluster_market_overlay(top_holdings, days=days, end_date=end_date)` |
| 持仓分布 `market_breakdown` | `cluster_market_breakdown(top_holdings)` |
| 距离直方图 `distance_histogram` | `cluster_distance_histogram([m.distance_to_center])` |
| 成员 NAV `member_value_rows` | `cluster_member_value_snapshot(days=days, end_date=end_date)` |
| 离散度 `dispersion` | `cluster_value_dispersion(member_value_rows)` |
| 综合净值 `composite_series` | `cluster_composite_value_series(member_value_rows, days=days, end_date=end_date)` |

**布局**（自上而下）：

```
1. 面包屑（相似度分析 → 运行摘要 → 簇标签）
2. 标题（簇标签 + 小字「· 簇 #N」+ JSON API 按钮）
3. Header card：簇规模 / HHI / Overlap / Top 行业 / Top 持仓 / 机构分布 / AC 份额合并
4. KPI 条卡（仅当 dispersion.n > 0 显示）：
     查询日 · 行情窗口 · N 只产品有完整起止净值
     6 个指标：平均涨跌幅 / 标准差 / 中位数 / 最大最小 / 正收益占比 / 极差 (pp) + 一致性徽章
     解读提示
5. 行情走势周期选择器：[30/60/90/180] 按钮 + 持仓分布徽章
6. 第一行图表：
   - 资产聚类（如 `kmeans-asset`）：3 张图 — Top 持仓水平条 / 行业分布 doughnut / 距离直方图
   - 行业聚类（如 `kmeans-industry`）：2 张图 — 行业分布 doughnut / 距离直方图（不渲染「Top 持仓」卡片，避免 `top_holdings` 实际为行业权重造成的概念混淆）
7. 第二行：簇综合净值与市场指数对比（合并图）— 见 §4.8.1
8. Top 5 / Bottom 5 双卡：
     「净值涨幅 Top 5」「净值跌幅 Top 5」
     列：# / 代码 / 名称 / 机构 / 区间涨跌幅 / 数据区间 / 持仓市值
     空态：「无足够数据（产品需要 ≥ 2 条 NAV 记录才能计算涨跌幅）」
9. 簇成员表：机构 / 代码 / 名称 / 类型 / 到质心距离 / 操作（归属）
```

#### 4.8.1 综合净值 + 市场指数对比图

**单一 canvas** `chartClusterMarket`，line chart，多 series 叠加：

- **综合净值 series**（第 1 条，实线 / 加粗 / 颜色 `colors[3]`）
  - 标签：`簇综合净值 (等权平均, 起点=100)`
  - 数据：在 `composite_series` 中查找匹配日期，`close.toFixed(2)`
  - `borderWidth: 2.5`，`pointRadius: 3`，`fill: false`
- **市场指数 series**（其余，虚线 `borderDash: [4, 3]`，颜色 `colors[(i+1) % colors.length]`）
  - 标签：`${symbol_name} (${symbol_code})`
  - 数据：所有日期并集上的归一化值（`close / base * 100`）
- **共享 x 轴**：所有日期的并集并升序
- **y 轴**：标题「标准化 (起始=100)」
- 交互：`interaction: { mode: 'index', intersect: false }`，tooltip 显示每个系列当前 x 对应值

**前端数据序列化**：模板用 `{{ ... | tojson }}` 把 Python dict 列表转成 JS 对象；变量名 `datasets`（市场指数）+ `composite`（综合净值）。

#### 4.8.2 KPI 条卡判定逻辑（`dispersion` 来源）

`dispersion` 字段（由 `cluster_value_dispersion` 计算）：

| 字段 | 含义 |
|---|---|
| `n` | 有 ≥ 2 条 NAV 记录的产品数（用于决定是否显示整张卡） |
| `mean_change` | 各成员自身区间涨跌幅的算术均值（带符号）；与综合净值涨跌幅口径不同，后者是等权合成净值从锚点到期末的变化 |
| `std_change` | 标准差 |
| `median_change` | 中位数；当成员涨跌幅分布接近对称时，通常与综合净值涨跌幅接近 |
| `max_change` / `min_change` | 最大 / 最小 |
| `positive_share` | 正收益占比 |
| `coefficient_of_variation` | std / |mean|，触发一致性徽章：<0.5 一致 / <1.5 分化 / ≥1.5 高分化 |
| `range_pct` | max - min（百分点） |
| `top5` / `bottom5` | 涨跌幅排序后的 5 条 |

颜色规则：`mean_change > 0 → text-success`、`mean_change < 0 → text-danger`。

## 7. 关键算法细节

### 7.1 簇标签派生（`derive_cluster_label`）

实现文件：`src/fundseeker/similarity/labels.py`（`fundseeker.similarity.labels`），被 similarity service 与 web queries 共用。

```python
def derive_cluster_label(
    top_industries: list[dict[str, Any]],
    *,
    max_pieces: int = 3,
    min_weight: float = 0.05,
) -> str | None:
    """取 top_industries 中权重 ≥ min_weight 的行业，按 _shorten_industry
    去后缀（Ⅱ/III/II/I/1/2/3），去重，取前 max_pieces 个，用 ' + ' 连接。
    例：白酒Ⅱ → 白酒；2 个行业 → "白酒 + 家电"；3 个 → "白酒 + 家电 + 消费"。
    """
```

**持久化**：`ClusterProfile` 在 `build_profiles()` 中调用 `derive_cluster_label(top_industries)`，结果写入 `cluster_label` 字段；`save_cluster_run()` 将其持久化到 `similarity_cluster.cluster_label`。

**路由层兜底**：

```
display_label = cluster.cluster_label or derived_label or f"簇 #{cluster.cluster_id}"
```

优先使用 service 已持久化的标签，以便支持后续人工覆盖；缺失时再用 `top_industries` 重新派生。

### 7.2 簇行情对比（`cluster_market_overlay`）

```python
def cluster_market_overlay(*, top_holdings, days, end_date=None):
    """按 top_holdings 推断主要市场区域：
    1. 计算 (market, weight) 累加
    2. 加入 baseline ['SH000300']
    3. 取权重最大的非 UNKNOWN 区域，加入其 bundle
    4. 若既有 domestic 又有 HK/US，再补一条 domestic bundle 做对比
    5. 对每个指数调用 market_quote_history(code, days=days, end_date=end_date)
    返回 Chart.js datasets 数组
"""
```

`MARKET_INDEX_BUNDLES`：

| 区域 | 指数 |
|---|---|
| `domestic` | `SH000300, SH000001, SZ399006` |
| `hk` | `HSI` |
| `us` | `NDX, SPX, DJIA` |
| `commodity` | `GOLD, BRENT_OIL` |
| `baseline` | `SH000300`（始终参与对比） |

### 7.3 成员 NAV 区间（`cluster_member_value_snapshot`）

**关键点：按逻辑产品 `(institution_code, product_code)` 聚合**。

1. 从簇成员 `product_id` 找出对应 `institution_code` / `product_code`
2. 用 `(inst, code)` 查出所有兄弟 `product_info.id`（同一逻辑产品的多次采集快照）
3. 拉取窗口 `[end_date - days, end_date]` 内的所有 NAV
4. 同一日期去重（保留首次出现的值）
5. 排序后取 `earliest` / `latest`，计算 `period_change_pct = (latest - earliest) / earliest`
6. 窗口内仅 1 条 NAV → `period_change_pct = None`（不参与排名）

返回每行字段：`product_id, product_code, product_name, institution_code, product_type, latest_nav_date, latest_unit_nav, earliest_nav_date, earliest_unit_nav, span_days, nav_record_count, period_change_pct, holding_market_value, holding_weight, window_start, window_end`

### 7.4 离散度（`cluster_value_dispersion`）

输入：`cluster_member_value_snapshot` 的 rows（仅取 `period_change_pct is not None` 的行）。

输出：

| 字段 | 计算 |
|---|---|
| `n` | 行数 |
| `mean_change` | 平均 |
| `std_change` | numpy std (ddof=1) |
| `median_change` | numpy median |
| `max_change` / `min_change` | 最大 / 最小 |
| `coefficient_of_variation` | std / \|mean\|（避免符号翻转） |
| `positive_share` | `(arr > 0).mean()` |
| `range_pct` | max − min（百分点） |
| `top5` / `bottom5` | 按 `period_change_pct` 排序取 5 |
| `mean_nav` / `min_nav` / `max_nav` | 仅 latest_unit_nav 的兼容字段 |

### 7.5 综合净值时序（`cluster_composite_value_series` / `_build_composite_series`）

1. 收集所有成员的 `(inst, code)` 逻辑键
2. 查出每个键的所有兄弟 `product_id`
3. 窗口内拉取所有 NAV
4. 每个逻辑产品一个 `series[date → value]`（同日期去重）
5. 按日期聚合：`by_date[d] = [每个成员的 NAV]`，等权平均
6. **锚点选择**：取首个 **≥ 80% 成员覆盖** 的日期作为 100；之前的不全的日期保留但不作为锚点
7. 重新基准化：`close = raw / anchor_value * 100`

返回 `[{date: ISO, close: float}, ...]`。

**期间涨跌计算口径**：`cluster_composite_period_change` 与 `cluster_run_period_changes` 以锚点日期（`start_value = 100`）为起点、窗口末日为终点计算 `(end_value / 100 - 1)`，而不是用 `series[0]`。这样与簇详情页成员涨跌幅的「窗口内 earliest → latest」口径可比，同时避免早期成员覆盖不足带来的抽样偏差。

### 7.6 距离直方图（`cluster_distance_histogram`）

按 `n_bins=10` 等宽分箱距离值，返回 `[{bin, count}, ...]`。所有值为 `null` 时返回空。

4. **图表数据缺失时的占位**：当前 `if (marketCtx && (datasets.length || composite.length))` 静默通过；可考虑显示「无数据」占位文本。
5. **成员表分页**：`similarity_cluster_detail` 中 `list_similarity_members(..., limit=200)` 一次性渲染，大簇前端压力较大，应增加分页或虚拟滚动。
6. **缓存层**：`similarity_run_detail`、`similarity_cluster_detail` 单次请求触发多次 DB 查询，建议增加短期缓存（如 Flask-Caching）。
7. **移动端表格体验**：复杂表格在窄屏下仅靠横向滚动体验一般，可探索卡片列表或折叠面板。
