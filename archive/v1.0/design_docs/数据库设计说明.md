# FundSeeker 数据库设计说明

> 本文档详细说明 FundSeeker 项目当前 PostgreSQL 数据库的实体关系模型、各表字段数据字典及索引约束设计。
> 最后更新：2026-07-13

---

## 1. 设计概述

### 1.1 数据库定位

本数据库是 FundSeeker 理财产品数据采集与分析系统的核心存储，承担三类数据：

1. **采集原始数据**：产品基本信息、净值、收益、费率、持仓、行情等。
2. **参考数据**：证券基础信息、指数成分股权重。
3. **分析结果数据**：持仓相似性聚类、簇画像、Brinson 归因等计算结果。

### 1.2 设计原则

- **产品为中心**：`product_info` 是核心维度表，其他业务表通过 `product_id` 关联。
- **报告期切片**：持仓、资产配置、风格标签等按 `report_date` 切片，支持跨期分析。
- **结果表隔离**：相似性分析结果以 `similarity_` 为前缀，与采集表解耦。
- **JSONB 灵活扩展**：画像、分布、代表产品等半结构化数据使用 JSONB 存储。
- **级联删除**：结果表与采集表之间通过外键 `ON DELETE CASCADE` 保持一致性。

## 3. 表清单

| 表名 | 类别 | 说明 |
|------|------|------|
| `product_info` | 核心维度 | 产品基础信息，每日快照 |
| `product_nav` | 时序数据 | 产品单位净值、累计净值、日收益率 |
| `product_return` | 时序数据 | 产品多周期收益率 |
| `product_fee` | 时序数据 | 产品费率结构（管理费、托管费等） |
| `holding_report` | 报告期数据 | 持仓报告期（季报/年报） |
| `product_holding` | 报告期明细 | 产品在报告期内的持仓明细 |
| `product_asset_allocation` | 报告期明细 | 产品在报告期内的大类资产配置 |
| `product_holding_summary` | 报告期汇总 | 持仓报告摘要指标（集中度、前十大占比等） |
| `holding_security_info` | 参考数据 | 持仓中出现的证券基础信息 |
| `product_manager_style` | 衍生数据 | 产品/经理风格标签 |
| `market_quote` | 行情数据 | 指数、个股、商品日行情 |
| `index_constituent_weight` | 参考数据 | 指数成分股权重（沪深 300/中证 800 等） |
| `similarity_cluster_run` | 分析结果 | 一次聚类运行批次 |
| `similarity_clusters` | 分析结果 | 聚类簇画像 |
| `similarity_cluster_members` | 分析结果 | 簇与产品的成员关系 |
| `similarity_attribution` | 分析结果 | Brinson 归因结果 |
| `collection_log` | 运维日志 | 采集任务执行日志 |

- **表名**：小写，单词间下划线分隔。

- **普通索引**：`ix_<表名>_<字段>`。
- **外键**：`<从表>_<字段>_fkey`。
- **主键**：`<表名>_pkey`。

## 9. 备注与注意事项

1. **`product_info` 是快照表**：同一产品不同 `collect_date` 会生成多条记录，分析时需按 `collect_date` 去重或取最新。
2. **`product_holding.weight` 是小数**：0.085 表示 8.5%，非百分比格式。
3. **`market_quote.symbol_code` 用于个股行情**：个股代码格式为 `SH{code}` / `SZ{code}`，与 `holding_security_info.market` 对应。
4. **`similarity_attribution` 唯一约束已升级**：当前实际约束为 `(product_id, cluster_run_id, start_date, end_date, benchmark_type, benchmark_code)`，支持同 run 下多种指数基准并存。
5. **JSONB 字段**：`top_industries`、`top_holdings`、`institution_distribution`、`representative_*`、`params_json` 均为 JSONB，便于扩展但查询时需注意索引。
6. **`holding_security_info` 待完善**：当前 `industry_name` 大量为空，需持续补充申万/中信行业映射。
7. **时间戳字段由应用层维护**：`created_at` / `updated_at` 在数据库层未设置默认值或自动更新触发器，实际值由采集/分析程序在写入时填充。
