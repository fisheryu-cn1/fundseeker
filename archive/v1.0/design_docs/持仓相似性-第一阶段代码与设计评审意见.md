## 2. 关键 Bug / 设计偏离（必须修复）

### 🚨 Bug #1：`cluster_run_id` 语义错位，导致历史数据已污染

**位置**：[src/fundseeker/similarity/persistence.py:90-108](../src/fundseeker/similarity/persistence.py#L90-L108)

**问题描述**

实现里没有独立的"运行批次"概念。`save_cluster_run` 用 `cluster_id_to_db_id` 中**第一条记录的 `id`** 作为所有成员的 `cluster_run_id`。结果是用 `cluster_id=0` 的 `SimilarityCluster.id`（如 k=12 时为 11，k=5 时为 6）兼任"运行 ID"。

**实测验证**

查询 `similarity_cluster_member` 表（report_date='2026-03-31'）：

```
cluster.id  k   cid  size  member_cnt
  6      5    0    396   1101   ← k=5 全员挂在 id=6 上
  7      5    1     59      0   ← 同 run 的其他簇成员 = 0
  8      5    2      8      0
  9      5    3     57      0
 10      5    4    581      0
 11     12    0    185   1101   ← k=12 全员挂在 id=11 上
 12-22  12    *      *      0   ← 同 run 的其他簇成员 = 0
```

**导致后果**

1. **CLI `list` 不传 `--k` 时返回 `total_members: 0`**：
   - `load_cluster_run` 按 `created_at desc` 取首条记录，其 id 不再等于任一成员的 `cluster_run_id`，因此 `members` 为空。
2. **同一 run 内只能查到 1 个簇对应的成员记录**，其余 4 / 11 个簇的成员全为 0。
3. 唯一能"碰巧正确"的场景是恰好指定 `--k=12`（第一条 `cluster_id=0` 的 id 正好被用作 `cluster_run_id`）。
4. 这是 **数据已污染 + 表面正常** 的组合，未来任何 schema/算法调整都会再次触发隐性错误。

**修复建议**

需要真正的"运行批次"概念。可选方案：

- **方案 A（推荐）**：新增 `similarity_cluster_run` 表：

  ```sql
  CREATE TABLE similarity_cluster_run (
      id BIGSERIAL PRIMARY KEY,
      report_date DATE NOT NULL,
      algorithm VARCHAR(30) NOT NULL,
      k INT NOT NULL,
      product_type_filter VARCHAR(100),
      params_json TEXT,
      silhouette DECIMAL(10, 6),
      inertia DECIMAL(20, 6),
      n_products INT,
      n_assets INT,
      created_at TIMESTAMP NOT NULL DEFAULT NOW(),
      UNIQUE (report_date, algorithm, k, product_type_filter, created_at)
  );
  ```

  `similarity_cluster_member.cluster_run_id` 改为外键引用该表。

- **方案 B**：在 `SimilarityCluster` 上新增 `run_id` 字段（UUID 或独立 bigserial），让所有同 run 记录共享同一 `run_id`，但与 `cluster.id` 解耦。

**数据回填**

无论选哪种方案，都需要对现有数据进行回填：

```sql
-- 1. 为每个 (report_date, algorithm, k) 生成一个 run_id
-- 2. 将 similarity_cluster_member.cluster_run_id 修正为对应的 run_id
-- 3. 删除仅作为"占位"的 cluster_id=0 重复成员记录
```

### 🚨 Bug #2：表结构与设计文档不一致（Type / 命名）

**位置**：[src/fundseeker/models/tables.py:633-720](../src/fundseeker/models/tables.py#L633-L720)

设计文档 §7.1 明确给出 `similarity_clusters`（**复数**）、`similarity_cluster_members`、`JSONB` 等，但实现是：

| 设计文档 | 实际实现 | 偏离 |
|---------|---------|------|
| 表名 `similarity_clusters`（复数） | `similarity_cluster`（单数） | 命名 |

| `top_holdings JSONB` | `Text` | 类型 |
| `institution_distribution JSONB` | `Text` | 类型 |
| `representative_products JSONB` | `Text` | 类型 |

- 与文档不一致，CLI / 查询 / Agent 集成时需要硬编码新名字。

```sql
ALTER TABLE similarity_clusters
    ALTER COLUMN top_industries TYPE JSONB USING top_industries::JSONB,
    ALTER COLUMN top_holdings TYPE JSONB USING top_holdings::JSONB,
    ALTER COLUMN institution_distribution TYPE JSONB USING institution_distribution::JSONB,
```

### 🚨 Bug #3：A/C 份额去重可能误伤同机构不同产品

**位置**：[src/fundseeker/similarity/features.py:48-80](../src/fundseeker/similarity/features.py#L48-L80)

**实现逻辑**

基于"机构 + 去后缀基础名"分组，保留 holdings 最多者。**当 `product_code` 前缀不同的同基名产品因命名差异而被错误归并时，会被合并。**

**实测验证**

```python
# 输入
df = pd.DataFrame({
    'product_id': [1, 2],
    'product_name': ['医药基金A', '医药基金'],
    'institution_code': ['HXA', 'HXA'],
})
# 去重后仅保留 id=1（'医药基金A'），丢掉 id=2（'医药基金'）
```

**已知局限**

- `name.endswith(" H")` 把港股份额 H 当成去重目标，但港股 ETF 等产品也可能以 H 结尾。
- `name.endswith(" E")` 没有在文档中解释为何剔除（增强指数 / 专户？）。
- 该函数完全靠"产品名称 + 机构"启发式，**未参考 `product_code`**，而方案 §6.1 明确"按 `product_code` 前缀或名称相似度识别 AC 份额"。

**修复建议**

更稳健的归一化路径：

1. **优先**用 `product_code` 前缀匹配（去除末尾字母 A/B/C/E/H 后相同 code → 同份额组），例如 `002604` / `008213` 来自同一根 `002604`。
2. **回退**到名称匹配（基础名 + 机构）。
3. 在画像或日志中**标记"被合并"的产品 ID**，便于回溯与人工核验。

```python
def _ac_share_code(code: str) -> str:
    """Strip trailing A/B/C/E/H from product code to find share-class family."""
    return re.sub(r"[ABCEH]$", "", code)
```

## 3. 性能与正确性（重要）

### 4. `compute_silhouette` 全量 n×n 距离矩阵，规模膨胀风险

**位置**：[src/fundseeker/similarity/clustering.py:132-167](../src/fundseeker/similarity/clustering.py#L132-L167)

- 当前 1101 产品 × 1095 资产 ≈ 8.6 MB float64 距离矩阵，无问题。
- 但 `select_k_silhouette` 对每个候选 k 都要重算一次全量 `n×n` 距离（**不缓存**）。k_min=3, k_max=12 共 10 次，每次约 0.06s ≈ 0.6s 总体可接受；当 n 增长到 10k+ 时此设计会爆。
- `dist_sq` 计算公式 `x² + y² - 2xy` 在浮点累加下可能产生微小负值；silhouette 内部已用 `np.maximum(dist_sq, 0.0)` 兜底（OK），但 K-Means 内的 `_squared_distances` **没有此兜底**，长时间迭代可能累加负值 → `np.argmin` 取错。

**建议**

- 缓存 `X @ X.T` 给 silhouette 用，或分块计算。
- `_squared_distances` 同样加 `np.maximum(_, 0.0)`。

### 5. K-Means 空簇处理：再初始化为"随机点"会引入不稳定性

**位置**：[src/fundseeker/similarity/clustering.py:106-113](../src/fundseeker/similarity/clustering.py#L106-L113)

```python
new_centers[c] = X[rng.integers(X.shape[0])]
```

- 用 `seed + iteration + c` 派生 RNG，**仍然受主 seed 控制**，但每次迭代可能重复挑到同一个点（X 的不同行也可能相同）。
- 高维稀疏场景下，空簇较常见；如果空簇被重新"塞"一个随机产品作为质心，下一次迭代该点很可能独享一个新簇。
- 这会让"簇内代表性产品"出现偶然选中的边缘产品。

**建议**

空簇时选择离当前所有质心最远的点（k-means++ 风格的 "explore from farthest"），而不是任意随机点：

```python
if not np.any(mask):
    # Pick the point farthest from all existing centers
    dist_sq = _squared_distances(X, centers)
    farthest_idx = int(np.argmax(dist_sq.min(axis=1)))
    new_centers[c] = X[farthest_idx]
```

### 7. `_overlap_pairwise` 的"对归一化向量的意义"需要在文档中明确

**位置**：[src/fundseeker/similarity/profiling.py:31-48](../src/fundseeker/similarity/profiling.py#L31-L48)

**实测验证**

| 场景 | 计算值 | 备注 |
|------|--------|------|
| A=[0.5,0.5], B=[0.5,0.0], C=[0.0,0.5]（原始权重） | avg_overlap = 0.333 | 与直觉一致 |
| A=[1/√2, 1/√2], B=[1,0], C=[0,1]（归一化） | avg_overlap = 0.471 | 数值变化大 |
| A=[0.01, 0.01]（低权重但同仓），B=[0.5, 0.5] | 归一化后 min(0.014, 0.707) = 0.014 | **市值影响被低估** |

**问题**

`build_profiles` 传入的 `X_c = fm.X[mask]` 是**归一化后**的矩阵，但 `avg_hhi` 用的是 `raw_weights`。两者的"重仓同持仓"含义不一致。

**建议**

- 在 `ClusterProfile.avg_overlap` 注释中明确"基于 L2-归一化权重向量"。
- 原始权重（`raw_weights`）下的 overlap 更接近业务直觉，可作为补充指标一并输出：`avg_overlap_raw`。
- 在画像输出中区分 `top_holdings` 的 weight 是归一化后的质心权重（当前实现），与原始权重的语义差异需要在文档中说明。

### 8. `select_k_silhouette` 不收集 SSE，缺失"肘部法则"对账

**位置**：[src/fundseeker/similarity/clustering.py:170-208](../src/fundseeker/similarity/clustering.py#L170-L208)

- 要么在注释中明确"肘部规则延后到引入行业特征后启用"。

### 11. `product_types` 过滤参数被转为 `tuple` 但保留了字符串边界 case

**位置**：[src/fundseeker/similarity/cli.py:41](../src/fundseeker/similarity/cli.py#L41), [service.py:73](../src/fundseeker/similarity/service.py#L73)

```python
product_types=tuple(args.product_types.split(",")) if args.product_types else None
```

- 空字符串 `""` 会触发 `args.product_types=False` 分支走 `None`，OK。
- 但 `"  "`（仅空格）会被 split 成 `[""]`，成为 `("",)` 进入 SQL，触发 `IN ('')` 报错。
- `load_holdings` 内部 `product_types = product_types or ("equity", "mixed")` 兜底，但 split 出空字符串这种 case 仍会让 SQL 报错。

**建议**：解析时加 `if v: v.split(",")`，或直接抛错"无效 product_types"。

### 12. `product_type_filter` 存储格式 `equity,mixed` 与设计文档不一致（无唯一约束）

**位置**：[src/fundseeker/similarity/service.py:104](../src/fundseeker/similarity/service.py#L104), [persistence.py:60-66](../src/fundseeker/similarity/persistence.py#L60-L66)

设计 §7.1 `similarity_clusters` 表中 `product_type_filter VARCHAR(100)` 注释示例是 `equity,mixed`，OK；但**没有唯一约束**，意味着同一 `(report_date, algorithm, k)` 可以写入多条不同 `product_type_filter` 的记录。下次再以默认类型聚类时，旧成员不会被清理（delete 条件不含 product_type_filter），会出现**多套 k=5 结果并存**。

**建议**：

- 在 `SimilarityCluster` 上加 `(report_date, algorithm, k, product_type_filter)` 唯一约束。
- delete 同步增加 `product_type_filter` 条件。
- 同时这是 Bug #2 修复（增加 `similarity_cluster_run` 表）时一并处理的自然位置。

```python
record = SimilarityCluster(

```

## 5. 实测数据与基线

### 5.1 当前聚类规模

| 项 | 数值 |
|----|------|
| 当前产品数（去重后） | 1101 |
| 资产（标的）维度 | 1095 |

### 7.7 修复后仍存在的次要风险

#### ⚠ 1. `holding_security_info.industry_name` 仅 1287/1495 覆盖（86%）

148 个标的缺行业（多为 HK 4 位代码未补 0、未上市新股等）。`build_industry_weights` 中所有缺行业记录全部归入 `"未知行业"`，会污染行业聚类结果（实测簇 3 的 top1 就是 `"未知行业"`）。

**建议**：在 `industry.py` 的 `update_security_industries` 中追加对 `industry_name IS NULL` 标的的二次匹配（如按 `asset_name` 模糊匹配），或允许 CLI 报告 `missing_count`。

#### ⚠ 2. AC dedup 守门规则 `has_suffix >= 2` 在边界 case 下过于严格

考虑：机构 X 名下有 `'医药基金A'`（id=1）和 `'医药基金'`（id=2），它们**事实上**确实是同一产品的 A 份额（机构用 id=1 上报完整持仓，id=2 是另一份快照少了一条记录）。当前规则会保留两者。

**取舍**：当前规则偏保守（宁可漏合并），避免误合并。生产中应配合 `product_code` 前缀二次校验。**方案文档 §6.1 已写明"按 `product_code` 前缀或名称相似度识别"**，未来加入 `product_code` 前缀匹配会更准。

**建议**：把 7.3 节 6 个 AC dedup case 沉淀为 pytest 单元测试，作为 `_base_name` 与 `deduplicate_ac_shares` 的回归保险。

#### ⚠ 3. `params_json` 缺少运行后修改的 detection

`save_cluster_run` 写入时记录配置，但如果未来从 `holding_security_info` 读取的 mapping 在两次运行间变化，重跑无法感知。建议在 `SimilarityClusterRun` 增加 `industry_mapping_version` 或 `industry_mapping_hash` 字段。
